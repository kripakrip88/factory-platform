# Бэкапы и восстановление

Два независимых уровня. Они решают разные задачи и не заменяют друг друга.

| | Бегет (снапшот VPS) | Наш cron (логические дампы) |
|---|---|---|
| Что снимает | Всю машину целиком | Только БД (+ вложения раз в неделю) |
| Частота | Раз в 2–4 дня (по загрузке их системы) | Ежедневно в 03:00 |
| Хранит | До 10 копий | Дампы БД 14 дней, архивы вложений 28 дней |
| Где лежит | **Отдельный дата-центр**, на двух серверах | На том же диске, `/opt/factory-platform/backups/erp` |
| Стоимость | Бесплатно, входит в VPS | — |
| Для чего | «Сервер/диск умер» — поднять всё заново | «Откатить БД на вчера» перед рискованным деплоем |
| Восстановление | Через панель Бегета (весь сервер или отдельные файлы) | `bench restore` / `psql` (ниже) |

**Offsite покупать не нужно** — Бегет уже держит копии в отдельном ДЦ. Гостевой
агент `beget-agent` на сервере запущен, через него хост снимает снапшот.
Документация: [резервное копирование VPS](https://beget.com/ru/kb/manual/rezervnoe-kopirovanie-vps).

Чего **не** покрывает ни один уровень: переполнение диска. Снапшот от него не спасает,
поэтому в скрипте стоит предохранитель — при свободном месте < 5 ГБ бэкап не начинается
и пишет `❌ ОТМЕНА` в лог.

## Наш скрипт

`services/erp/scripts/backup.sh`, ставится через `install-cron.sh`
(cron `0 3 * * *`, лог `/var/log/erp-backup.log`).

Что снимает:

| Источник | Файл | Размер | Частота |
|---|---|---|---|
| ERPNext PROD, БД | `<стамп>-erp_localhost-database.sql.gz` | ~52 МБ | ежедневно |
| ERPNext PROD, вложения | `<стамп>-erp_localhost-private-files.tar` | ~1.6 ГБ | **раз в неделю (вс)** |
| n8n | `postgres/n8n-<стамп>.sql.gz` | ~84 КБ | ежедневно |
| factory (под AI) | `postgres/factory-<стамп>.sql.gz` | ~0.4 КБ | ежедневно |
| Роли Postgres | `postgres/globals-<стамп>.sql.gz` | ~0.5 КБ | ежедневно |
| brain-db | `postgres/brain-<стамп>.sql.gz` | ~116 КБ | ежедневно |

Итого ~52 МБ в сутки, по воскресеньям +1.6 ГБ.

### Два решения, которые важно понимать

**Вложения — раз в неделю, а не ежедневно.** Они весят 1.6 ГБ и почти не меняются.
Ежедневная копия давала +1.6 ГБ/сутки и к сентябрю 2026 съела 13 ГБ диска (87%
заполнения) — при том что сама БД 52 МБ. Вложения при этом не остаются без защиты:
они в снапшотах Бегета и в недельном архиве.

**История выполнений n8n в дамп не входит.** Таблица `execution_data` — 533 МБ из
551 МБ всей n8n-БД, и она расходная (логи прогонов). Без неё дамп 84 КБ вместо 258 МБ,
в 3000 раз меньше. Схема таблиц сохраняется, восстановление работает — просто без
логов прошлых прогонов. Воркфлоу, креденшелы и настройки (то, что реально жалко) —
в дампе есть.

### Staging не бэкапится

Сознательно: это расходная среда, восстанавливается клоном с prod —
`services/erp/scripts/clone-prod-to-staging.sh`.

## Восстановление

### ERPNext (БД prod)

```bash
# 1. ВСЕГДА сначала свежий бэкап текущего состояния
ssh factory 'docker exec erp-backend-1 bench --site erp.localhost backup'

# 2. Положить нужный дамп в контейнер
ssh factory 'docker cp /opt/factory-platform/backups/erp/<дамп>.sql.gz \
  erp-backend-1:/tmp/restore.sql.gz'

# 3. Восстановить (снесёт текущую БД сайта!)
ssh factory 'docker exec erp-backend-1 bench --site erp.localhost \
  restore /tmp/restore.sql.gz'

# 4. Миграции + сброс кэша
ssh factory 'docker exec erp-backend-1 bench --site erp.localhost migrate'
ssh factory 'docker exec erp-backend-1 bench --site erp.localhost clear-cache'
```

Вложения (если нужны): добавить к `restore` флаги
`--with-public-files <files.tar> --with-private-files <private-files.tar>`.

### n8n

```bash
# распаковать и залить (пароль берётся из env контейнера, в командах его нет)
ssh factory 'gunzip -c /opt/factory-platform/backups/erp/postgres/n8n-<стамп>.sql.gz \
  | docker exec -i infra-postgres-1 sh -c "psql -U \$POSTGRES_USER -d n8n"'
ssh factory 'docker restart infra-n8n-1'
```

⚠️ n8n 2.x: правка воркфлоу прямо в БД **не подхватывается** — менять только через
`publish:workflow` + restart (см. память `project_n8n_publish`).

### Весь сервер

Через панель Бегета → раздел бэкапов. Можно поднять сервер целиком или вытащить
отдельные файлы.

## Проверка что всё живо

```bash
ssh factory 'tail -20 /var/log/erp-backup.log'
ssh factory 'ls -lah /opt/factory-platform/backups/erp/ | tail; ls -lah /opt/factory-platform/backups/erp/postgres/'
ssh factory 'df -h / | tail -1'
```

Признаки здоровья: в логе последняя строка `✅ Бэкап завершён`, дневной прирост
каталога ≤ 100 МБ (кроме воскресенья), свободного места > 10 ГБ.

Скрипт при любой частичной ошибке пишет `❌` и выходит с кодом 1 — раньше он мог
упасть посередине и всё равно отрапортовать «✅ завершён».

## Воркфлоу n8n (для справки при восстановлении)

На 16.09.2026 в n8n **один** воркфлоу — «Автоклассификация писем (v2, смотровой режим)»
(`kyOWFTcrKsTYVI9Y`), и он **выключен**: на API Anthropic кончились средства. Его определение
лежит рядом с бэкапами: `backups/erp/n8n-workflow-kyOWFTcrKsTYVI9Y-20260916.json`.

```bash
# включить обратно (когда будет баланс)
ssh factory 'docker exec infra-n8n-1 n8n publish:workflow --id=kyOWFTcrKsTYVI9Y && docker restart infra-n8n-1'
# выключить
ssh factory 'docker exec infra-n8n-1 n8n unpublish:workflow --id=kyOWFTcrKsTYVI9Y && docker restart infra-n8n-1'
```

⚠️ Перед включением поправить расписание: нода называется «Каждые 15 минут», а настроена
`minutesInterval: 1` — раз в минуту (1440 прогонов в сутки вместо 96).

### 533 МБ логов ошибок — что с ними

`execution_data` в n8n-БД раздута логами падений этого воркфлоу. Прунинг n8n работает
(дефолт: max age ~14 дней, max count 10 000) и строки удаляет — видно по счётчику
прогонов, который падает без новых запусков. Но **Postgres при удалении строк не отдаёт
место файловой системе**: оно становится переиспользуемым внутри БД, а файл остаётся
тем же. То есть `pg_database_size` так и покажет ~551 МБ.

Практически ничего делать не надо: БД больше не растёт, 550 МБ при 21 ГБ свободного —
не проблема, и место переиспользуется под будущие данные. Если место понадобится
физически: `VACUUM FULL` по БД n8n (берёт эксклюзивную блокировку, n8n на это время
недоступен) — делать только осознанно, не в рамках рутины.
