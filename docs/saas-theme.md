# SaaS Theme — документация

Кастомная UI-тема для ERPNext на базе Frappe Framework.
Хранится в `services/erp/saas_theme/`, собирается в Docker-образ при деплое.

## Что делает тема

### Workspace Rail (левая узкая панель, 60px)

Дополнительная панель слева от стандартного sidebar Frappe.

- Показывает иконки всех workspace (модулей) из `frappe.boot.desktop_icons`
- **Цветные иконки** — каждый модуль имеет уникальный цвет:

| Модуль | Цвет |
|--------|------|
| CRM | Индиго `#6366F1` |
| Продажи (Selling) | Синий `#3B82F6` |
| Закупки (Buying) | Янтарный `#F59E0B` |
| Склад (Stock) | Зелёный `#10B981` |
| Производство (Manufacturing) | Красный `#EF4444` |
| HR / Персонал | Фиолетовый `#8B5CF6` |
| Проекты | Голубой `#06B6D4` |
| Бухгалтерия (Accounting) | Розовый `#EC4899` |
| Основные средства (Assets) | Оранжевый `#F97316` |
| Поддержка (Support) | Бирюзовый `#14B8A6` |

Для неизвестных модулей — цвет определяется детерминированно по первой букве названия.

- **Активный модуль** — цветной фон + левая полоска-акцент + яркая иконка
- **Тултипы** — всплывают при ховере с названием модуля
- **Переключатель темы** — кнопка в нижней части rail (светлая/тёмная)
- Клик по иконке — переключает sidebar на выбранный workspace

### ListView — ресайз колонок

- Drag-handle на правом краю каждого заголовка колонки
- Потянуть → изменить ширину колонки
- Ширины сохраняются в `localStorage` с ключом `st_col_w__<DocType>`
- Восстанавливаются автоматически при следующем открытии списка

### Прочее

- Переработанный user menu (убраны лишние пункты "Upgrade to Pro", "Update App")
- Улучшенные карточки вложений (attachments) в форме документа
- Логин-страница: центрированная карточка

├── saas_theme/

| Модуль | Назначение |
|--------|-----------|
| `saas_theme.sidebar` | Workspace rail, переключение модулей, тема |
| `saas_theme.columns` | Ресайз колонок ListView |
| `saas_theme.attachments` | Улучшенные карточки вложений |

## Деплой

Тема подключается в `hooks.py`:
```python
app_include_css = "/assets/saas_theme/css/saas_theme.css?v=76"
app_include_js  = "/assets/saas_theme/js/saas_theme.js?v=76"
```

**Правило**: при каждом изменении JS или CSS — инкрементировать `?v=N` в `hooks.py`. Это сбрасывает браузерный кэш.

### Как добавить изменение

1. Отредактировать `saas_theme.js` или `saas_theme.css`
2. Увеличить версию в `hooks.py` (`v=76` → `v=77`)
3. Запушить в `develop` — CI/CD пересоберёт образ и задеплоит

## Инфраструктурные фиксы

### fix_assets.py

**Проблема**: `assets.json` хранится в Docker volume `erp_assets`. CSS/JS файлы хранятся в image layer (симлинки `assets/frappe` → `apps/frappe/frappe/public`). При каждом новом `docker build` генерируются новые хэши файлов, но volume сохраняет старый `assets.json` → браузер запрашивает несуществующие файлы → верстка ломается.

**Решение**: скрипт `fix_assets.py` запускается при старте backend контейнера (перед `start.sh`) и синхронизирует записи `assets.json` с реально существующими файлами на диске.

### nginx Cache-Control

В `frappe.conf` добавлен заголовок:
```
Cache-Control: no-cache, must-revalidate
```
для location `@webserver` (динамические HTML/API ответы).

Статические ассеты (`/assets/*`) кэшируются вечно — имена файлов содержат хэш, при изменении хэш меняется.
