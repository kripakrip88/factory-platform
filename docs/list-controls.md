# Единая кнопка «Настройка таблицы» на списках (saas_theme)

Слой поверх штатных списков Frappe v16: одна кнопка в шапке списка управляет
**фильтрами** и **видимостью колонок**. Реализован в `saas_theme` (Client Script +
CSS), ядро Frappe не патчится — слой снимается, родное цело.

## Решение по видимости колонок (важно)

**Колонки скрываются персональным CSS-слоем по имени поля, НЕ через штатное хранилище.**

### Почему не штатный механизм (List View Settings.fields)
Разведка и живой тест на списке Лидов показали:
1. **Колонку ID (`name`) убрать штатно нельзя** — ядро Frappe всегда форс-добавляет
   её в `setup_columns()` независимо от `fields`. Родной picker её тоже не убирает.
2. **List View Settings — ОДИН на доктайп, общий для всех пользователей.** «Менеджер
   скрыл колонку у себя» так не выходит — меняется список для всех.
3. Снятие `in_list_view`-колонки через `save_listview_settings` создаёт **глобальный
   Property Setter** (меняет схему доктайпа). Это тяжёлый общий побочный эффект.

### Как сделано (безопасно + переживает обновления)
- Видимость колонок — `display:none` по классу поля: `.list-row-col.<fieldname>`
  (Frappe кладёт имя поля CSS-классом на ячейку и в шапке, и в строках).
- Скоуп per-doctype: к контейнеру списка добавляется класс `st-lc-<scrub(doctype)>`,
  правило `.st-lc-lead .list-row-col.name{display:none}` действует только на этот список.
- Состояние (набор скрытых полей) — в **localStorage** ключом `st_hidden_cols_<doctype>`
  (персонально по пользователю/браузеру). На бэкенд ничего не пишем.
- **Frappe-данные/схему НЕ трогаем** → при обновлении Frappe нечему «полететь».
  Если Frappe сменит вёрстку и класс поля исчезнет — правило просто не сработает,
  колонка снова покажется (мягкая деградация, список не ломается).
- Полностью обратимо: убрать слой `saas_theme` → все колонки видны.
- Работает для **любой** колонки, включая ID.

### Что осталось на штатном механизме
- **Добавление новых полей и порядок колонок** — родной picker
  `cur_list.show_list_settings()` (это уже общая настройка доктайпа, помечено в UI).
- **Фильтры** — штатный `cur_list.filter_area` (чтение/убрать/очистить) + родной
  popover для добавления. Своей логики/хранилища фильтров нет.

## Ключевые штатные API (на чём держится слой)
- `cur_list.page.add_inner_button(...)` — кнопка в шапке.
- `cur_list.filter_area` (`get`, `clear`, `filter_list.get_filters()[i].remove()`),
  `cur_list.get_filters_for_args()`.
- `cur_list.show_list_settings()` — родной конструктор колонок (хранилище
  `List View Settings`, серверные `get/set_list_settings`).
- Ячейка колонки: `.list-row-col` с классом = `fieldname` (для CSS-таргетинга).

## Распространение
Этап 2-3 — прототип на Лидах (кнопка гейтится `lv.doctype === "Lead"`). CSS-скрытие
(`apply_hidden_columns`) и тултипы заголовков работают на любом списке. Распространять
кнопку на сделки/покупатели/инбокс — после подтверждения стабильности на Лидах
(снять гейт в `try_render`).
