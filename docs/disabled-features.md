# Реестр отключённых элементов

Документ фиксирует все поля, модули, кнопки и строки интерфейса, которые были
скрыты или отключены в ERPNext. Перед разработкой новой функциональности —
сверяться с этим документом: возможно, нужное уже есть в системе и просто отключено.

**Правило:** любое изменение видимости полей через Property Setter или Custom Field
обязательно отражается в этом документе.

## Единицы измерения — Вариант А (ручной)

Текущая схема учёта металла — упрощённая, без автоматического пересчёта.

Кастомная логика (`MW Material Definition`) — отложена на следующий этап.

### Как устроен учёт сейчас

- Закупка у поставщика — в **тоннах**
- Заявки инженеров — в **штуках** (вариант номенклатуры по длине)
- Производство/раскрой — в **миллиметрах**
- Коэффициент пересчёта шт→тн прописывается **вручную** для каждого варианта длины

### Структура номенклатуры

Каждый профиль — шаблон с вариантами по длине:

- Уголок 50х50х5 / 6000мм
- Уголок 50х50х5 / 11700мм
- Уголок 50х50х5 / 12000мм

Коэффициент (шт → тн) = погонный вес (кг/м) × длина (м) ÷ 1000

### Обрезки

Обрезок создаётся вручную как отдельная номенклатура при возврате со склада.

Хранится на складе "Обрезки" отдельно от целых прутков.

### Схема учёта длин (гибридная)

**Склад Металлопрокат** — целые хлысты стандартных длин:
- Учёт через варианты номенклатуры по атрибуту `Длина` (6000 / 11700 / 12000 мм)
- Стандартный отчёт ERPNext "Остаток запасов по размерам" работает из коробки
- Вес единицы (кг) прописан в каждом варианте = погонный вес × длина

**Склад Обрезки** — остатки после раскроя любой длины:
- Отдельная номенклатура с суффиксом -ОБР для каждого профиля
- Учёт через партии (Batch) с кастомным полем `length_mm`
- Длина обрезка вводится кладовщиком вручную при возврате из производства
- В будущем: модуль раскроя будет формировать возврат автоматически

**Ограничение текущей схемы:**
Нестандартные длины (не 6000/11700/12000) на основном складе не поддерживаются.
Если поставщик привезёт хлысты другой длины — создать новый вариант вручную.

### Что даёт следующий этап (MW Material Definition)

Автоматический пересчёт тонн из штук через погонный вес профиля.

Резервирование обрезков под заявку до заказа у поставщика.

Оптимизация раскроя.

## Карточка письма (Communication) — скрытые секции в режиме чтения

Скрыты из вида формы Communication (через saas_theme.js `reshape_mail` + CSS,
класс `.st-mail-hide`). **Данные и поля НЕ удалены** — только скрыт UI; всё
доступно через API и при снятии класса. Сделано для удобного чтения письма
менеджером (карточка чтения + оценки), не редактор техдокумента.

| Секция | Поля | Что даёт при включении |
|--------|------|------------------------|
| Статус | text_content, communication_type, status, seen | Текстовая версия письма, тип/статус коммуникации, отметка прочтения |
| Дополнительная информация | communication_date, read_receipt, rating | Дата коммуникации, запрос уведомления о прочтении, рейтинг |
| Связи шкалы времени | timeline_links, link_doctype, link_name | Привязки письма к нескольким документам (таймлайн) |
| Входящие электронной почты | message_id, uid, imap_folder, message_index | Технические IMAP-идентификаторы письма |

**Оставлены видимыми:** Тема (как заголовок), «Кому и копия» (отправитель/копии),
тело письма, блок «Классификация (эксперимент)» (наверху), «Ссылка»
(reference_doctype/reference_name — через неё ручная привязка письма к лиду).

Кнопка «Переподключить» приглушена (`.st-mail-hide`) — правка письма не нужна.
«Сохранить» оставлена (для сохранения оценки менеджера).

Длинные письма (рассылки на тысячи px) клампятся до ~680px с кнопкой
«Показать письмо полностью» — это поведение, не скрытие данных.

Откат: убрать вызов `saas_theme.reshape_mail` / классы `.st-mail-*` из saas_theme.
