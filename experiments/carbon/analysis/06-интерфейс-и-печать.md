# Carbon: интерфейс, формы, печать и PDF — что и сколько стоит доработать

Источник: клон `crbnos/carbon`, ветка по состоянию на 2026-09-16.
Правила разработчика лежат прямо в репозитории: `.claude/rules/*.md` (59 файлов) —
это не маркетинг, а внутренняя техническая документация, синхронизируемая с кодом
(правило `.claude/rules/keep-sources-in-sync.md`: «код главнее документа, документ
чинится, а не игнорируется»).

---

## 0. Главные выводы (для решения «брать / не брать»)

1. **Бумага уже A4, не Letter** — для всех «настоящих» документов (счёт, заказ,
   КП, заказ поставщику, упаковочный лист, маршрутный лист). Жёстко зашито в одном
   месте: `packages/documents/src/pdf/components/Template.tsx:75` — `<Page size="A4">`.
   US Letter (8.5×11") остался только в **этикетках на листовом носителе**
   (`ProductLabelPDF.tsx:57-58`, `KanbanLabelPDF.tsx:53-54`). Перевод их на A4 —
   правка 4 строк + 1 тест. Это НЕ проблема.
2. **Настоящая проблема — кириллица в PDF.** В шрифты вшит только латинский
   набор глифов: `packages/documents/scripts/generate-fonts.mjs:19` → `const SUBSET = "latin"`.
   Плюс запасной шрифт — `Helvetica` (встроенный шрифт PDF, тоже без кириллицы,
   `packages/documents/src/pdf/fonts.ts:10`). **Русский текст в PDF выйдет пустыми
   квадратами / пробелами.** Это обязательная доработка, оценка — 1-2 дня.
3. **Русский интерфейс уже переведён**: `packages/locale/locales/ru/erp.po` —
   6487 строк, из них без перевода всего 32. Термины адекватные
   («Purchase Order» → «Заказ поставщику», «Work Center» → «Рабочий центр»,
   «Routing» → «Маршрут операций»). MES: 510 строк.
4. **Добавить своё поле без программиста — можно** (механизм Custom Fields,
   ~55 таблиц поддержано, поле сразу появляется в форме, в колонках таблицы,
   в CSV-выгрузке и доступно как блок в PDF).
5. **Добавить свой экран — это код**, но по жёсткому шаблону из 4 файлов.
   В репозитории 128 готовых таблиц и 177 готовых форм как образцы для копирования.
6. **Российских печатных форм (УПД, ТОРГ-12, счёт-фактура, М-11, МХ-1) в коде НЕТ.**
   Каталог документов закрытый: `packages/documents/src/template/schema.ts:379-391` —
   11 типов. Добавление нового типа — работа программиста (см. §9.4).

## 1. Из чего собран интерфейс

### 1.1 Стек (`.claude/rules/coding-conventions.md`)

| Слой | Технология |
|------|-----------|
| Монорепо | pnpm workspaces + Turborepo; `apps/*` и `packages/*` |
| Фреймворк | **React Router v7** (не Remix, не Next.js), плоские маршруты через `remix-flat-routes` |
| Язык | TypeScript везде |
| Данные | Supabase/Postgres, типы генерируются в `@carbon/database`; Kysely для транзакций |
| Стили | Tailwind v4, темы через CSS-переменные (`packages/utils/src/themes.ts`) |
| Таблицы | TanStack Table |
| Анимация | framer-motion |
| Фоновые задачи | Inngest (`@carbon/jobs`) |
| Переводы | Lingui v5.9.4 |

Приложения: `apps/erp` (основное), `apps/mes` (цех, планшеты у станков),
`apps/academy`, `apps/starter`, `docs` (Next.js + Fumadocs).

### 1.2 Библиотека компонентов — она уже есть, писать свою не надо

- **`packages/react/src/`** — 99 файлов-примитивов, плоско, баррель
  `packages/react/src/index.tsx`: `Button`, `Card`, `Drawer`, `Modal`, `HStack`,
  `VStack`, `Combobox`, `MultiSelect`, `Table`, `Tabs`, `Popover`, `Progress` и т.д.
- **`packages/form/src/components/`** — 28 полей формы: `Input`, `Number`,
  `Select`, `Combobox`, `CreatableCombobox`, `MultiSelect`, `Boolean`, `Radios`,
  `DatePicker`, `DateTimePicker`, `TimePicker`, `Timezone`, `Password`,
  `PhoneInput`, `InputOTP`, `Array`, `ArrayNumeric`, `Hidden`, `Submit`.
- **`apps/erp/app/components/Form/index.ts`** — поверх них ~55 **доменных
  селекторов**, которые сами подгружают справочники: `Customer`, `Supplier`,
  `Employee`, `Item`, `Part`, `Location`, `WorkCenter`, `Process`, `UnitOfMeasure`,
  `Currency`, `PaymentTerm`, `Shift`, `Tool`, `Tags`, `CostCenter`, `Account`…
  При добавлении формы вы не пишете выпадающий список клиентов — вы пишете
  `<Customer name="customerId" label={t`Клиент`} />`.
- **`apps/erp/app/components/`** — ~90 прикладных компонентов
  (`Table/`, `Grid/`, `Editable/`, `TreeView/`, `Gantt/`, `Modals/`, `Selectors/`,
  `DocumentTemplateEditor/`, `ImportCSVModal/`, `Configurator/`).

Правило репозитория (`.claude/rules/conventions-ui.md`, раздел «Use Existing
Components First»): прежде чем писать разметку — грепнуть `packages/react/src/`.
Ад-хок классы `bg-*`/`text-*` вместо `variant` считаются ошибкой ревью.

### 1.3 Навигация: где заводится пункт меню

- Модули верхнего уровня — `apps/erp/app/hooks/useModules.tsx:47+`
  (`useModuleDefinitions()`): массив `{ key, permission, name, to, icon }`.
  Отфильтровывается правами (`filterByPermissions`, строки 31-44).
- Подпункты внутри модуля — отдельный хук на модуль, например
  `apps/erp/app/modules/sales/ui/useSalesSubmodules.tsx` — группы
  `{ name: t`Manage`, routes: [{ name, to, icon, table }] }`.
  Поле `table` связывает пункт меню с «сохранёнными видами» (saved views).
- Отрисовка — `apps/erp/app/components/Layout/Navigation/PrimaryNavigation.tsx`
  (+ `MobileNavigation.tsx`, `HiddenModulesPopover.tsx`). Пользователь может сам
  скрывать/переставлять модули (`useNavigationEditMode.tsx`).
- Права — enum `module` в БД: `packages/database/supabase/migrations/20230123004409_permissions.sql:2`
  (Accounting, Documents, Invoicing, Inventory, Jobs, Messaging, Parts, Purchasing,
  Resources, Sales, Settings, Scheduling, Timecards, Users; позже расширялся).
  Новый модуль прав = миграция БД, не просто строка в TS.

### 1.4 Хлебные крошки и URL

- URL **никогда не пишутся строкой**: типизированный хелпер
  `apps/erp/app/utils/path.ts` (2401 строка) — `path.to.customers`,
  `path.to.customerStatus(id)`. Правило из `conventions-forms.md`, чеклист.
- Крошка задаётся в маршруте: `export const handle: Handle = { breadcrumb: msg`Customer Statuses`, to: path.to.customerStatuses }`
  (пример — `apps/erp/app/routes/x+/sales+/customer-statuses.tsx:12-15`).
  `msg` — из `@lingui/core/macro`, резолвится в
  `apps/erp/app/components/Layout/Topbar/Breadcrumbs.tsx`.

## 2. Как устроена одна фича: 4 обязательных слоя

Правило `.claude/rules/conventions-forms.md` описывает жёсткий трёхчастный шаблон,
`conventions-services.md` добавляет четвёртый. Файлы модуля
(`apps/erp/app/modules/{module}/`, всего 19 модулей: sales, purchasing, production,
inventory, items, invoicing, accounting, quality, resources, people, users,
settings, documents, agent, workflows, storage-rules, shared, account):

```
modules/{module}/
├── {module}.models.ts    # zod-валидаторы  (19 файлов в репо)
├── {module}.service.ts   # операции с БД   (19 файлов)
├── {module}.server.ts    # серверные хелперы (опционально)
├── index.ts              # баррель: export * from "./..."
└── ui/                   # компоненты (837 .tsx файлов суммарно)
```

### Слой 1 — валидатор (zod), `{module}.models.ts`

```typescript
import { z } from "zod";
import { zfd } from "zod-form-data";

export const thingValidator = z.object({
  id: zfd.text(z.string().optional()),
  name: z.string().min(1, { message: "Name is required" }),
  quantity: zfd.numeric(z.number().min(0)),
  isActive: zfd.checkbox(),
});
```

Таблица соответствий (из `conventions-forms.md`): необязательная строка →
`zfd.text(z.string().optional())`; число из FormData → `zfd.numeric(...)`;
галочка → `zfd.checkbox()`; повторяющееся поле → `zfd.repeatableOfType(...)`;
межполевые проверки → `.refine()` / `.superRefine()`.

### Слой 2 — сервис, `{module}.service.ts`

Жёсткая форма функции: **первый аргумент — клиент, возвращается сырой
`{ data, error }`, исключения не бросаются, `data` не разворачивается**.

```typescript
export async function getCustomer(client: SupabaseClient<Database>, id: string) {
  return client.from("customer").select("*").eq("id", id).single();
}
```

Списки обязаны принимать `companyId` и прогонять
`setGenericQueryFilters(query, args, [{ column: "name", ascending: true }])`
(`~/utils/query`) — это даёт поиск/сортировку/пагинацию «бесплатно», из URL.
Мультитенантность: `.eq("companyId", companyId)` — даже при включённом RLS,
как «защита в глубину».

Именование (таблица из `conventions-services.md`):
`getCustomer` / `getCustomers` / `getCustomersList` / `upsertCustomer` /
`insertCustomerContact` / `deleteCustomer` / `updateQuoteLineOrder(db, ...)`.

Многострочные записи — через Kysely-транзакцию `db.transaction().execute(...)`,
не `Promise.all`. **Клиент БД нельзя создавать внутри сервиса** — иначе серверный
код утечёт в браузерный бандл; это проверяется автоматически
(conformance-проверка `no-db-client-in-service` в `@carbon/checks`).

### Слой 3 — форма, `ui/{Feature}/{Feature}Form.tsx`

`ValidatedForm` из `@carbon/form`, в проп `validator` кладётся **сырая zod-схема**.
Контейнер — `ModalDrawer*` (выдвижная панель) либо `Card`/inline, «как у соседей».

```tsx
<ValidatedForm validator={thingValidator} method="post"
  action={isEditing ? path.to.thing(id) : path.to.newThing}
  defaultValues={initialValues} fetcher={fetcher} className="flex flex-col h-full">
  <Hidden name="id" />
  <VStack spacing={4}>
    <Input name="name" label={t`Название`} />
    <Select name="type" label={t`Тип`} options={typeOptions} />
    <CustomFormFields table="thing" />     {/* ← пользовательские поля */}
  </VStack>
  <HStack><Submit isDisabled={isDisabled}>{t`Сохранить`}</Submit>
    <Button variant="solid" onClick={onClose}>{t`Отмена`}</Button></HStack>
</ValidatedForm>
```

Права управляют доступностью кнопки: `permissions.can("update", "things")`.

### Слой 4 — action маршрута, `routes/x+/{module}+/{resource}.new.tsx`

```typescript
export async function action({ request }: ActionFunctionArgs) {
  assertIsPost(request);
  const { client, companyId, userId } = await requirePermissions(request, { create: "things" });
  const formData = await request.formData();
  const validation = await validator(thingValidator).validate(formData);
  if (validation.error) return validationError(validation.error);   // 422
  const insert = await upsertThing(client, { ...validation.data, companyId,
    createdBy: userId, customFields: setCustomFields(formData) });
  if (insert.error)
    return data({}, await flash(request, error(insert.error, "Failed to create thing")));
  throw redirect(path.to.things, await flash(request, success("Thing created")));
}
```

Правила (жёсткие, из `conventions-forms.md`):
- `validator(schema).validate(formData)` — **единственное** место, где схема
  оборачивается; `schema.parse()` запрещён;
- `json(...)` запрещён (наследие Remix), только `data(value, init)` или объект;
- при успехе — `throw redirect(...)`, не `return redirect(...)`;
- пользовательские поля пробрасываются через `setCustomFields(formData)`
  (`apps/erp/app/utils/form.ts:50-64` — берёт все поля с префиксом `custom-`).

### Тосты (уведомления) — `.claude/rules/flash-system.md`

Одноразовое сообщение кладётся в cookie-сессию (`flash(request, success("..."))`),
на следующем запросе читается и гасится. Рендерится **middleware**, не `useEffect`:
`flashMiddleware` (сервер) + `flashClientMiddleware` (клиент) регистрируются в
`root.tsx`, клиентский вызывает `toast.success/error` из `@carbon/react`.
Грабли: корневой loader обязан вернуть И `result`, И заголовки — иначе cookie не
гасится и сообщение всплывает повторно на каждой навигации.

### Клиентский кэш — `.claude/rules/clientAction-patterns.md`

Только в ERP (~25 файлов `clientLoader`, ~63 `clientAction`; в MES не используется).
Кэш — TanStack `QueryClient` на `window.clientCache`, создаётся в
`apps/erp/app/root.tsx` с `staleTime: Infinity` (живёт сессию).
Ключи — фабрики из `apps/erp/app/utils/react-query.ts`, **всегда с `companyId`**.
После мутации маршрут инвалидирует ключ и делегирует на сервер:

```ts
export async function clientAction({ serverAction }: ClientActionFunctionArgs) {
  window.clientCache?.setQueryData(thingsQuery(getCompanyId()).queryKey, null);
  return await serverAction();
}
```
Оптимистичных обновлений нет — только инвалидация.

## 3. Как добавить СВОЁ ПОЛЕ

Три уровня по возрастанию стоимости.

### 3.1 Без программиста: Custom Fields (настройка в интерфейсе)

Таблицы: `customFieldTable` (реестр таблиц, куда можно добавлять) и
`customField` (сами поля) —
`packages/database/supabase/migrations/20240311021818_custom-fields.sql:1-41`.

Колонки `customField`: `id`, `name`, `sortOrder`, `table`, `dataTypeId`,
`listOptions TEXT[]`, `active`, `companyId` + аудит. Значения лежат в JSON-колонке
`customFields` самой записи.

- Экран настройки: `apps/erp/app/routes/x+/settings+/custom-fields.tsx`,
  `custom-fields.$table.tsx`, `.new.tsx`, `.$id.tsx`, `.delete.$id.tsx`.
- Поле сразу отрисовывается в форме — если форма содержит
  `<CustomFormFields table="customer" />`
  (`apps/erp/app/components/Form/CustomFormFields.tsx`). Поддержаны типы:
  `Boolean`, `Date`, `Number`, `Select` (по `listOptions`), `Input`, а также
  доменные `Customer` / `Supplier` / `Employee` (строки 1-14, switch по
  `field.dataTypeId`). Обязательность (`field.required`) валидируется на клиенте
  через `useAdditionalValidatorsContext` (строки 41-56). Есть теги (`field.tags`) —
  поле можно показывать только в определённом контексте.
- Поле сразу появляется **колонкой в таблице** — `useCustomColumns("customerStatus")`
  (пример подключения: `apps/erp/app/modules/sales/ui/CustomerStatuses/CustomerStatusesTable.tsx:32,48`).
- Поле сразу попадает **в CSV-выгрузку** (см. §6).
- Поле можно вывести **в печатную форму** — блок `customField` в конструкторе
  шаблонов (`packages/documents/src/template/schema.ts:211-219`).

Поддержано ~55 таблиц (`customFieldTable`), среди них: `customer`, `part`,
`material`, `consumable`, `tool`, `fixture`, `gauge`, `job`, `quote`, `shipment`,
`payment`, `account`, `location`, `department`, `process`, `equipment`,
`methodOperation`, `methodMaterial`, `makeMethod`, `nonConformance`, `journal`,
`holiday`, `currency`, `contractor`, `partner`, `memo`, `partner` и др.

**Для завода металлоконструкций это закрывает большую часть «своих полей»**:
марка стали, ГОСТ, номер чертежа КМД, № сертификата на металл, вес нетто/брутто,
класс покрытия, № ППР. Без единой строки кода.

**Чего Custom Fields НЕ дают:** индекса в БД, серверной валидации (проверка
только на клиенте), участия в SQL-отчётах на равных с обычной колонкой,
вычисляемых значений, связи «многие-ко-многим».

### 3.2 Настоящая колонка в БД (нужен программист)

Последовательность (`.claude/rules/conventions-database.md` + `conventions-forms.md`):

1. `pnpm db:migrate:new <name>` → SQL-миграция в
   `packages/database/supabase/migrations/`. Золотые правила: у таблицы есть
   `companyId`, составной PK `("id","companyId")`, id через `id('prefix')`
   (не голый UUID), аудит-колонки `createdBy/createdAt/updatedBy/updatedAt`,
   RLS-политики со стандартными именами `SELECT/INSERT/UPDATE/DELETE`.
2. Перегенерировать типы `@carbon/database` (**руками не править** — правило).
3. Добавить поле в zod-валидатор в `{module}.models.ts`.
4. Добавить поле в форму (`ui/.../XxxForm.tsx`).
5. При необходимости — в колонки таблицы и в блок PDF.

Реально это 5 файлов и полдня-день на простое поле.

### 3.3 Поле в печатной форме

- Если поле уже есть в данных — добавить его в соответствующий блок PDF
  (`packages/documents/src/pdf/blocks/<doc>/`), например в
  `LineItemsBlock.tsx` или `PartiesBlock.tsx`.
- Если это custom field — блок `customField` добавляется **пользователем мышкой**
  в конструкторе шаблонов, без кода.
- Если нужна произвольная строка/подвал — блоки `richText`, `keyValue`, `field`
  с merge-полями `{company.name}`, `{invoice.number}`, `{customer.city}` и т.д.
  (каталог — `packages/documents/src/template/merge.ts:58+`).

## 4. Как добавить СВОЙ ЭКРАН

Минимальный набор файлов (на примере списка «Статусы клиентов», который можно
брать как эталон):

| № | Файл | Что делает |
|---|------|-----------|
| 1 | `app/modules/{m}/{m}.models.ts` | zod-схема |
| 2 | `app/modules/{m}/{m}.service.ts` | `getThings` / `upsertThing` / `deleteThing` |
| 3 | `app/modules/{m}/index.ts` | добавить экспорт в баррель |
| 4 | `app/modules/{m}/ui/Things/ThingsTable.tsx` | таблица-список |
| 5 | `app/modules/{m}/ui/Things/ThingForm.tsx` | форма создания/правки |
| 6 | `app/routes/x+/{m}+/things.tsx` | loader + default (список) |
| 7 | `app/routes/x+/{m}+/things.new.tsx` | action создания |
| 8 | `app/routes/x+/{m}+/things.$id.tsx` | loader + action правки |
| 9 | `app/routes/x+/{m}+/things.delete.$id.tsx` | подтверждение удаления |
| 10 | `app/utils/path.ts` | `path.to.things`, `path.to.thing(id)` |
| 11 | `app/modules/{m}/ui/use{M}Submodules.tsx` | пункт в меню |

Маршрут-список целиком (реальный код,
`apps/erp/app/routes/x+/sales+/customer-statuses.tsx`):

```tsx
export const handle: Handle = { breadcrumb: msg`Customer Statuses`, to: path.to.customerStatuses };

export async function loader({ request }: LoaderFunctionArgs) {
  const { client, companyId } = await requirePermissions(request, { view: "sales", role: "employee" });
  const searchParams = new URLSearchParams(new URL(request.url).search);
  const { limit, offset, sorts, filters } = getGenericQueryFilters(searchParams);
  return await getCustomerStatuses(client, companyId,
    { search: searchParams.get("search"), limit, offset, sorts, filters });
}

export default function CustomerStatusesRoute() {
  const { data, count } = useLoaderData<typeof loader>();
  return (<VStack spacing={0} className="h-full">
    <CustomerStatusesTable data={data ?? []} count={count ?? 0} />
    <Outlet />   {/* сюда рендерятся дочерние .new / .$id как выдвижные панели */}
  </VStack>);
}
```

Это ~47 строк на весь экран-список. Форм и таблиц-образцов в репо очень много:
**128 файлов `*Table.tsx` и 177 файлов `*Form.tsx`** в `apps/erp/app/modules`.
Суммарно в ERP 1503 файла маршрутов — то есть шаблон обкатан.

**Оценка:** простой справочник (список + форма + удаление) — 0.5-1 день
программиста. Экран с бизнес-логикой (документ со строками, статусами,
действиями) — 3-10 дней.

## 5. Как добавить СВОЮ ТАБЛИЦУ

Таблица приложения — `apps/erp/app/components/Table/Table.tsx`
(не путать с `packages/react/src/Table.tsx` — тот просто обёртка над `<table>`).

Опции `TableProps` (`Table.tsx:91-153`) — то, что даётся бесплатно:

`columns`, `data`, `count`, `compact`, `defaultColumnOrder`, `defaultColumnPinning`,

## 6. Выгрузка в CSV (`.claude/rules/table-csv-export.md`)

Кнопка «Скачать CSV» есть **у каждой** таблицы автоматически, отключить можно
пропом `withCsvExport={false}`. Никакого «включения» не требуется.

- Реализация: `apps/erp/app/components/Table/components/Download.tsx`,
  библиотека `json-2-csv` (`json2csv(rows, { emptyFieldValue: "" })`).
- Имя файла жёстко `data.csv` (Blob + клик по ссылке, без обращения к серверу).
- Выгружается **текущая страница/результат**, а не полный серверный дамп — важный
  момент для отчётности: для «всего справочника» нужно поднять `limit` в URL.
- Колонки берутся из текущего сохранённого вида (порядок + видимость).
- Подстановка имён вместо id работает только для accessorKey
  `itemId` / `supplierId` / `employeeId` / `customerId` и только если у колонки
  нет своего `meta.exportValue`.
- Грабли: `accessorKey` с символом `_` роняет таблицу целиком
  (`buildColumnMaps` в `utils.ts` бросает исключение); точечный accessor
  (`"item.name"`) выгружается пустым — нужен `meta.exportValue`.

Есть и отдельный механизм импорта: `importCSV` проп таблицы +
`apps/erp/app/components/ImportCSVModal/` + `fieldMappings` в `~/modules/shared`
(подробно — `.claude/rules/csv-import-system.md`).

## 7. Печать и генерация PDF

### 7.1 Архитектура (`.claude/rules/pdf-generation-patterns.md`)

PDF — это **React-компоненты** на `@react-pdf/renderer` **v3.4.5** (не v4 —
примеры из документации v4 не подходят), стилизуемые через `react-pdf-tailwind`.
Живут в `packages/documents/src/pdf/`.

Два стиля авторства:

1. **Блочные, настраиваемые пользователем** — 12 документов:
   `SalesInvoicePDF`, `SalesOrderPDF`, `SalesReturnOrderPDF`, `PurchaseOrderPDF`,
   `PurchaseReturnOrderPDF`, `QuotePDF`, `PackingSlipPDF`, `StockTransferPDF`,
   `JobTravelerPDF`, `IssuePDF`, `BatchListPDF`, `ProductLabelPDF`.
   Файл документа — тонкий «драйвер»: резолвит шаблон и рендерит упорядоченный
   список блоков.
2. **Жёстко свёрстанные** (не настраиваются): `KanbanLabelPDF.tsx`,
   `StorageUnitLabelPDF.tsx`.

Общая «обвязка страницы» — `packages/documents/src/pdf/components/Template.tsx`:
`<Document><Page size="A4" style={styles.body}>`, поля `padding: "10px 16px 36px 16px"`,
`lineHeight: 1.4`, чёрный текст на белом фоне; фиксированный `<Footer>` и
повторяющийся `headerContent`. Прочие общие части (`pdf/components/`):
`Header`, `Footer`, `AddressBlock`, `LogoImage`, `Note`, `Summary`, `Watermark`,
`labelGeometry.ts`.

Стилизация внутри блока — **не** `StyleSheet`, а темизированный Tailwind:
```tsx
const tw = useTw();
<Text style={tw("text-[9px] font-bold text-gray-600 uppercase")}>Ship To</Text>
```
`makeDocTw(theme)` переопределяет `gray-600` → цвет заголовков темы,
`gray-800` → цвет текста. Меняешь тему — перекрашивается весь документ.

### 7.2 Как PDF отдаётся пользователю

19 маршрутов в `apps/erp/app/routes/file+/`, имена вида
`file+/sales-invoice+/$id[.]pdf.tsx` (`[.]` — экранированная точка в
`remix-flat-routes`). Канонический порядок (реальный код `sales-invoice`):

```
requirePermissions(request, { view: "sales" })
→ Promise.all([...все нужные данные + getDocumentTemplate...])
→ toDocumentTemplate(row, "salesInvoice")     // единственная точка приведения JSON
→ resolveTemplate("salesInvoice", config)     // подмешивает дефолты
→ resolveSections(client, companyId, collectSectionIds(resolved))
→ await ensureFont(resolved.settings.fontFamily)   // ДО рендера
→ renderToStream(<SalesInvoicePDF ... />)     // не renderToBuffer
→ ручной слив Node-потока в Buffer
→ new Response(new Uint8Array(body), { "Content-Type": "application/pdf",
     "Content-Disposition": `inline; filename="..."` })
```

Важное правило: **вся асинхронщина — до рендера** (шрифты, QR-коды, картинки
превращаются в data-URL заранее); дерево компонентов синхронное.

### 7.3 Штрих-коды и QR

`packages/documents/src/qr/` на `@bwip-js/node` v4.9.0 (пакета `qrcode` нет):
- `generateQRCode(text, size, color?)` → `data:image/png;base64,...`;
- `generateBarcode(text, symbology, opts?)`, symbology:
  `"pdf417" | "code128" | "datamatrix" | "qrcode"`.
- `generateQRCodeSync` существует, но **бросает исключение** — вызывать нельзя.

### 7.4 Шрифты — здесь же зарыта проблема кириллицы

`packages/documents/src/pdf/fonts.ts` + сгенерированный (и gitignore-нутый)
`fonts.data.ts`:

- Все шрифты вшиты в пакет как **base64 woff** и регистрируются в процессе,
  без обращения в сеть (раньше тянулись с Google Fonts и падали на Vercel).
- Формат именно **woff, не woff2**: react-pdf поддерживает только TTF/WOFF, а его
  декодер woff2/brotli портит общее состояние при множественном декодировании.
- Вариативные (variable) шрифты запрещены — react-pdf не умеет их сабсетить.
- Список семейств — `packages/documents/scripts/generate-fonts.mjs:20-29`:
  Inter, Roboto, Open Sans, Lato, Montserrat, Merriweather, Playfair Display, Lora.
  Плюс встроенные в PDF Helvetica / Times-Roman / Courier
  (`fonts.ts:10`, регистрация не нужна).
- `getSafeFontFamily(family)` — если семейство не зарегистрировано, молча
  подставляет **Helvetica**, чтобы рендер не падал (`fonts.ts:31-38`).

> **`packages/documents/scripts/generate-fonts.mjs:19`:
> `const SUBSET = "latin";`** — в пакет попадает только латинский набор глифов
> (комментарий в коде: «latin subset = Western European, keeps the bundle small»).

Следствие для России: кириллица в PDF не отрисуется ни одним из 11 предлагаемых
шрифтов. Подробности и оценка — §10.

## 8. Конструктор шаблонов документов (`.claude/rules/document-template-customizer.md`)

Это сильная сторона Carbon и главная причина, по которой «печатные формы под себя»
здесь дешевле, чем кажется.

### 8.1 Хранение

Миграция `packages/database/supabase/migrations/20260609143732_document-template.sql`:

- **`documentTemplate`** — PK `("id","companyId")`, `UNIQUE (companyId, documentType)`
  (один шаблон на тип документа на компанию). Колонки: `documentType TEXT`
  (обычный текст, **не** enum Postgres), `formatVersion INTEGER DEFAULT 1`,
  `blocks JSONB`, `theme JSONB`, `settings JSONB`, `headerSectionId`/`footerSectionId`
  (мягкие ссылки, без FK — удалённая секция просто пропускается при рендере).
  RLS привязан к модулю Settings (`settings_create/update/delete`).
- **`documentSection`** — переиспользуемые rich-text секции компании:
  `placement` (`body|header|footer`), `content JSONB`, `config JSONB`
  (для шапки — логотип и какие реквизиты компании показывать; для подвала —
  строка регистрации/ИНН). Правка встроенной секции **форкает** её в строку БД.

Единственная точка приведения JSON к типам — `toDocumentTemplate(row, type)`
в `packages/documents/src/template/schema.ts`.

### 8.2 Что именно можно настроить мышкой

Редактор: `apps/erp/app/components/DocumentTemplateEditor/` —
`index.tsx`, `context.tsx`, `BlockList.tsx`, `BlockConfig.tsx`, `FontConfig.tsx`,
`ThemeConfig.tsx`, `SectionFormModal.tsx`, `TemplatePreview.tsx`,
`MergeFieldMenu.tsx`, `LogoCropper.tsx`, `labelConfigs.tsx`,
`useTemplateConflict.tsx`. Маршруты: `apps/erp/app/routes/x+/templates+/$type.tsx`
(редактор) и `$type.preview.tsx` (живой предпросмотр, в том числе на реальной
записи через `previewId`).

**Блоки** (`packages/documents/src/template/schema.ts:232-259`, 27 типов):

*Встроенные, привязанные к данным (можно скрыть/переставить, настроить опции):*
`header` (логотип: вариант mark/icon, высота 16-120, кроп; показывать реквизиты /
название документа / номер), `watermark` (прозрачность, расположение, размер),
`parties`, `notes`, `details`, `lineItems` (миниатюры товара, зебра,
перенос/обрезка текста), `summary` (подпись строки налога), `terms`
(свой rich-text или подтягивание из настроек компании), `jobDetails`,
`operations` (печатать ли рабочие инструкции), `issueDetails`, `associations`,
`actionTasks`, `reviewers`.

*Блоки этикетки:* `labelHeading`, `labelRevision`, `labelQuantity`,
`labelTracking`, `labelEntityId`, `labelBarcode` (symbology qrcode/pdf417/
code128/datamatrix, расположение right/full/center, высота), `labelLogo`.

*Пользовательские, полностью добавляемые/удаляемые:*
`richText` (произвольный форматированный текст), `keyValue` (список «поле:значение»),
`spacer` (отступ / линия / **разрыв страницы**), `shared` (ссылка на общую секцию),
`field` (одна строка «подпись: значение»), `customField` (значение
пользовательского поля записи), `watermark`.

**Тема** (`themeSchema`): 4 цвета в HEX — `accent` (заливка шапки таблицы строк),
`accentForeground`, `heading`, `text`.

**Настройки** (`documentSettingsSchema`, строки 354-378): шрифт (11 вариантов),
`showPageNumbers`, `pageNumberFormat` (`"Page 1 of 3"` или `"Page 1"`),
`showRegistrationLine`.

**Merge-поля** (`template/merge.ts`): `{company.name}`, `{company.city}`,
`{company.country}`, `{company.taxId}`, `{company.eori}`, `{company.vatNumber}`,
`{company.registrationNumber}`, `{invoice.number}`, `{invoice.dateIssued}`,
`{invoice.dateDue}`, `{invoice.customerReference}`, `{invoice.currency}`,
`{order.number}`, `{order.date}`, `{customer.name}`, `{customer.addressLine1}`,
`{customer.city}`, `{customer.country}` и т.д. Подставляются в rich-text,
key-value, шапку и подвал (`interpolateContent`).

**Типы документов с настраиваемым шаблоном** — ровно 11
(`schema.ts:379-391`): `salesInvoice`, `salesOrder`, `salesReturnOrder`,
`purchaseOrder`, `purchaseReturnOrder`, `quote`, `packingSlip`, `stockTransfer`,
`jobTraveler`, `issue`, `trackingLabel`.

**Устойчивость к обновлениям:** `resolveTemplate(type, stored)` при чтении
доливает недостающие встроенные блоки **скрытыми** — то есть ваш настроенный
шаблон переживает обновление Carbon, новые блоки просто не включаются сами.

### 8.3 Что означает «добавить свой тип документа» (например, УПД)

Работа программиста, затрагивает 6 точек:
1. добавить строку в `documentTemplateTypeSchema` (`template/schema.ts:379`);
2. запись в `DOCUMENT_CATALOG` и `DEFAULT_TEMPLATES` (`template/defaults.ts`);
3. если нужны новые типы блоков — добавить в `blockSchema`, **плюс запись в
   `BLOCK_META` (обязательна для каждого типа)**, плюс ключ во **все** реестры
   блоков (реестр типизирован как `Record<DocumentBlockType, BlockRenderer>` —
   пропуск не скомпилируется);
4. новый драйвер `packages/documents/src/pdf/УпдPDF.tsx` + папка
   `pdf/blocks/упд/` (`types.ts`, `vars.ts`, компоненты, `registry.tsx`);
5. регистрация в `pdf/preview-documents.tsx` (`DOCUMENT_PDFS[type]`) и в
   барреле `pdf/index.ts`;
6. маршрут отдачи `apps/erp/app/routes/file+/упд+/$id[.]pdf.tsx`.

**Оценка одного документа в стиле российской унифицированной формы (УПД,
ТОРГ-12): 3-7 дней** — основная работа не в «движке», а в точной вёрстке
табличной формы и в добывании реквизитов (ИНН/КПП/ОКПО/расчётный счёт),
части которых в модели Carbon нет.

## 9. Печать этикеток и очередь печати (`.claude/rules/printing-system.md`)

Отдельная подсистема, для завода полезная (маркировка партий, ярлыки на изделия).

- Пакеты: `@carbon/printing` (реестр, маршрутизация по принтерам, UI-кнопка) и
  `@carbon/documents` (рендер PDF/ZPL).
- Типы документов печати (`packages/printing/src/registry.ts`):
  `productLabel` (источники: Receipt, Shipment, Operation, Entity, Job, Split,
  StockTransfer; по умолчанию ZPL), `kanbanCard` (только PDF),
  `storageUnitLabel` (по умолчанию ZPL).
- Очередь — таблица `printJob` (`generating | queued | printing | completed |
  failed`), realtime, автоочистка (completed >30 дней, failed >90 дней).
- Доставка на принтер — HTTP-эндпоинт «ProxyBox», ключ на маршрут принтера;

- Привязка «участок → принтер» лежит в `companySettings.printing` (JSONB),
  контексты: `default | shipping | receiving | inventory | workCenter`.
  Кэш конфигурации принтера — Redis, TTL 1 час.
- Автопечать: после проводки приёмки, отгрузки, разделения партии,
  завершения первой операции в MES.
- Обе Inngest-функции с `retries: 0`, дедупликация автопечати — 30 секунд.

**ZPL и кириллица:** генератор выставляет `^CI28` (UTF-8) —
`packages/documents/src/zpl/utils.ts:39` (`^XA^PW…^LL…^MNW^CI28`), но текст
печатается резидентным шрифтом `^A0N`

у Zebra (CG Triumvirate) кириллицу **не содержит** — потребуется загрузить TTF в
принтер и переключить команду на загруженный шрифт (`~DU` + `^CW`). Это правка
2-3 строк генератора + разовая процедура на принтере. В коде этого сейчас нет.

### 10.2 Насколько тяжело перевести печать на A4

**Полностраничные документы переводить не надо — они уже A4.** Это лучший из
возможных ответов: авторы Carbon изначально сделали метрический формат по
умолчанию (в системе есть и флаг `companySettings.useMetric`).

Остаётся привести к A4 **листовые этикетки**:

1. `packages/documents/src/pdf/ProductLabelPDF.tsx:56-58` — заменить константы
   на A4 в пунктах: `595.28 × 841.89` (210×297 мм). Логика центрирования сетки
   (строки 90-98) переиспользуется как есть, менять её не нужно.
2. `packages/documents/src/pdf/KanbanLabelPDF.tsx:52-54, 91` — то же самое.
3. `packages/documents/src/pdf/productLabelPDF.test.ts:49-61` — тест
   «multi-up sheets still print on a letter page» ожидает
   `[0, 0, 8.5*72, 11*72]`; поправить ожидание.
4. `packages/utils/src/labels.ts:45-49` — пресет `avery5163` (4×2″, американский)
   заменить/дополнить европейским пресетом с `rows`/`columns` под A4
   (например, 105×48 мм, 2 колонки × 6 рядов). Метрические пресеты в коде уже
   поддержаны: `label100x50mm`, `label50x25mm` (`metric: true`).

**Оценка: 2-4 часа работы + полдня на проверку реальной печатью.**
Единственный риск — если заказчик реально использует американские листы Avery,
то лучше не заменять, а добавить A4-пресеты рядом; тогда правка сводится к
«размер страницы берётся из пресета этикетки», это ещё пара часов.

### 10.3 Если захочется сделать размер бумаги настраиваемым

Добавить `pageSize: z.enum(["A4","Letter","A5"]).default("A4")` и
`orientation` в `documentSettingsSchema`, пробросить в проп `Template`
(`Template.tsx:75`) и в `FontConfig`/новый конфиг редактора. Это ~5 файлов,
1 день. Практической нужды для российского завода нет.

## 11. КРИТИЧНО: кириллица в PDF

### 11.1 Диагноз

- `packages/documents/scripts/generate-fonts.mjs:19` → `const SUBSET = "latin"`.
  Генератор берёт из `@fontsource/*` файлы вида `inter-latin-400-normal.woff`
  (строки 45-52, `findWoff`). В `BUNDLED_FONTS` попадают только латинские глифы.
- Запасной путь — `Helvetica` / `Times-Roman` / `Courier`
  (`packages/documents/src/pdf/fonts.ts:10`): это встроенные шрифты PDF со
  стандартной кодировкой WinAnsi — кириллицы в них нет.
- `getSafeFontFamily` (`fonts.ts:31-38`) не падает, а молча подставляет Helvetica.
  То есть **ошибки не будет — будет молча пустой PDF в русских местах.**
  Это самый неприятный класс дефектов: система «работает», а накладная выходит
  без названия товара.

### 11.2 Что придётся сделать

Ограничение движка: `Font.register({ family, fonts: [{ src, fontWeight }] })`
допускает **один файл на начертание**. Значит, нельзя «доложить» кириллический
сабсет рядом с латинским для того же веса — нужен один файл, содержащий оба
набора глифов.

План:
1. Взять полные (не сабсетированные, не variable) TTF/WOFF с кириллицей —
   Inter, Roboto, Open Sans, Lato, Montserrat кириллицу имеют; Merriweather,
   Playfair Display, Lora — **нет** (их придётся убрать из списка или оставить
   как «латинские»).
2. Поправить `generate-fonts.mjs`: либо `SUBSET = "cyrillic"` не поможет (нужен
   объединённый файл), поэтому корректнее — положить полные файлы шрифтов в
   `packages/documents/assets/fonts/` и читать их напрямую, минуя сабсеты
   fontsource.
3. Поменять запасной шрифт в `getSafeFontFamily` с `Helvetica` на
   кириллическую Inter, иначе fallback снова даст пустоту.
4. Проверить размер бандла: сейчас ~720 KiB base64 на 8 семейств; с кириллицей
   на 3-4 семейства будет сопоставимо.
5. Прогнать `pnpm --filter @carbon/documents build` (он же висит на корневом
   `postinstall` и на turbo-таске `@carbon/documents#build`).

**Оценка: 1-2 дня, включая проверку всех 19 PDF-маршрутов.**
Риск: описанные в правилах грабли react-pdf (woff2 ломает fontkit, variable-шрифты
не сабсетятся) — надо строго соблюдать «woff/ttf, статические начертания».

## 13. Чего в коде НЕТ (честный список)

Проверено грепом, не домысел:

1. **Нет визуального конструктора форм.** Форма = TypeScript-файл. Мышкой
   настраиваются только печатные шаблоны и пользовательские поля.
2. **Нет настройки размера/ориентации бумаги** в модели документа (§10.1).
3. **Нет российских печатных форм**: УПД, ТОРГ-12, счёт-фактура, М-11, МХ-1,
   ТТН, КС-2/КС-3 — ни одной. Каталог документов — 11 типов, все западные.
4. **Нет кириллицы в шрифтах PDF** (§11) и в резидентном шрифте ZPL (§9).
5. **Нет «сумма прописью»** (обязательный реквизит российских форм) — грепом
   не находится.
6. **Нет полей ИНН/КПП/ОКПО/БИК/р-с** как отдельных сущностей — есть общие
   `company.taxId`, `vatNumber`, `eori`, `registrationNumber`
   (merge-поля в `template/merge.ts:58-70`). Под российские реквизиты это
   придётся либо натягивать (taxId = ИНН), либо добавлять поля.
7. **CSV-выгрузка отдаёт текущую страницу**, а не весь набор (§6) — для
   «выгрузить весь справочник» нужен обходной приём.
8. **Имя файла CSV всегда `data.csv`.**
9. **`FlashOverlay` в MES — мёртвый код** (по признанию самого правила
   `flash-system.md`): компонент есть, нигде не вызывается.
10. Голландская локаль `nl` лежит на диске, но не подключена — орфан.

**Вывод по интерфейсу:** архитектура очень регулярная и хорошо задокументирована
изнутри (`.claude/rules/` — 59 правил, включая явные «грабли» и чеклисты ревью).
Любая доработка делается копированием одного из 128 готовых списков или 177 форм.
Это заметно дешевле в поддержке, чем самописный слой поверх ERPNext, но требует
именно TypeScript-разработчика — «настроить мышкой» здесь можно поля и печатные
бланки, а не экраны.

**Главный технический блокер для России — не бумага, а шрифты.** Бумага уже A4.
