это признают и держат под это отдельный регламент починки
(`.ai/plans/2026-08-27-translation-consistency-runbook.md`), где русский стоит
в очереди и **ещё не чинился** (починен только китайский).

## 2. Механика переводов

### 2.1 Что чем является

Есть **два разных «глоссария»**, их легко перепутать:

| Объект | Путь | Что это | Работает ли в рантайме |
|---|---|---|---|
| Каталоги сообщений (message catalogs) | `packages/locale/locales/{lang}/{erp,mes}.po` | Сами переводы интерфейса | Да |
| Рантайм-глоссарий (glossary) | `packages/glossary/src/terms.ts` — 427 терминов | Всплывающие подсказки к полям формы («что такое Method?») | Да |
| Переводческий глоссарий (approved terms) | `packages/locale/locales/glossary.json` — 449 терминов | Утверждённый перевод каждого доменного термина на 12 языков | **Нет**, только для конвейера перевода и чекера |

### 2.2 Конфигурация

`lingui.config.js` (корень репозитория):

```js
sourceLocale: "en",
locales: ["en","es","de","it","ja","zh","fr","pl","pt","ru","hi","tr","ko"],
fallbackLocales: { default: "en" },
format: "po",
catalogs: [
  { path: "packages/locale/locales/{locale}/erp",
    include: ["apps/erp/app","packages/react/src","packages/form/src",
              "packages/printing/src/ui","packages/glossary/src",
              "packages/onboarding/src","packages/workflows/src"],
    exclude: ["**/*.server.*","**/*.test.*","**/*.spec.*"] },
  { path: "packages/locale/locales/{locale}/mes",
    include: ["apps/mes/app","packages/react/src","packages/form/src",
              "packages/printing/src/ui"],
    exclude: [...] }
]
```

Список языков дублируется в рантайме: `packages/locale/src/config.ts:3-17`
(`supportedLanguages`) и `:42-56` (`languageNativeLabels`, «Русский»).
Добавление языка требует правки **обоих** файлов.

Версии закреплены в `pnpm-workspace.yaml:63-67` (`@lingui/cli`, `core`,
`macro`, `react`, `vite-plugin` = 5.9.4).

### 2.3 Как строка попадает в перевод

Четыре шага: **пометить → извлечь → скомпилировать → загрузить**.

**1. Пометить (mark).** В коде строка оборачивается макросом:

| Место | Как | Сколько файлов |
|---|---|---|
| JSX | `<Trans>Save</Trans>` из `@lingui/react/macro` | ~557 |
| Внутри компонента | `const { t } = useLingui(); t\`Save\`` | ~741 |
| Хлебные крошки, глоссарий | `msg\`Profile\`` из `@lingui/core/macro` — строит только дескриптор | `apps/erp/app/routes/x+/account+/profile.tsx:20` |

Важное ограничение, записанное в `.claude/rules/i18n-lingui-system.md:57-72`:
**нельзя** `import { t } from "@lingui/core/macro"` — `runtimeConfigModule` не
настроен, такой `t` уйдёт в глобальный синглтон Lingui, который никогда не
активируется, и SSR упадёт с «Attempted to call a translation function without
setting a locale».

**2. Извлечь (extract).** `pnpm lingui:extract` → `lingui extract --clean`
сканирует исходники и обновляет/подчищает `.po`. Затем
`pnpm lingui:clean` → `node ./scripts/strip-po-headers.mjs` вырезает
`POT-Creation-Date` и строки `#: путь:номер` (иначе половина диффа каждого PR —
шум; см. комментарий `scripts/strip-po-headers.mjs:1-11`).

**3. Скомпилировать (compile).** `pnpm lingui:compile` → `lingui compile
--namespace es` даёт `packages/locale/locales/{lang}/{erp,mes}.mjs`.
Эти файлы **в .gitignore** (`.gitignore:23`) и собираются при билде:
`turbo.json:5` — любая задача `build` зависит от `//#lingui:compile`,
описанной в `turbo.json:20-29`. В самих приложениях (`apps/erp/package.json`)
шага компиляции нет — он приходит из turbo.

Практический вывод: **на свежем клоне без сборки каталогов нет**, и загрузчик
вернёт `{}` — интерфейс будет английским. Это не баг, это порядок сборки.

**4. Загрузить (load).**

- Сервер: `apps/erp/app/services/lingui.server.ts:4-19` — `import.meta.glob`
  по `packages/locale/locales/*/erp.mjs`, `loadLinguiCatalogForRequest()`
  резолвит язык и лениво подгружает нужный каталог; если файла нет — `{}`.
  Идентичный файл у MES: `apps/mes/app/services/lingui.server.ts`.
- Клиент: `apps/erp/app/root.tsx:107-109` берёт язык из заголовков/куки,
  грузит каталог, кладёт в loader-данные; `root.tsx:291` рендерит
  `<LocaleProvider locale={appLanguage} catalog={linguiCatalog}>`.
- `packages/locale/src/i18n.tsx:12-27` — `LocaleProvider` на каждый рендер
  создаёт **свой** runtime через `setupI18n()`, делает `load()` + `activate()`
  и оборачивает детей в `I18nProvider` Lingui. Это единственный активный
  экземпляр i18n.

Отдельно, не путать: `root.tsx:292` вкладывает ещё один `<I18nProvider>`, но
уже из `@react-aria/i18n` — он отвечает за форматирование дат/чисел и ARIA,
к Lingui отношения не имеет.

### 2.4 Выбор языка

Цепочка (`packages/utils/src/headers.ts:6-38`, `getPreferenceHeaders`):

1. Кука `locale` (имя задано в `packages/locale/src/config.ts:28`).
2. Если куки нет — первый валидный язык из заголовка `Accept-Language`.
3. Иначе `en-US`.
4. Если в куке лежит голый `ru`, а браузер просит `ru-RU` — берётся `ru-RU`
   (`headers.ts:28-33`), чтобы даты и числа форматировались по-русски.

Дальше `resolveLanguage()` (`packages/locale/src/config.ts:30-39`) обрезает
регион (`ru-RU` → `ru`) и проверяет по `supportedLanguages`; если языка нет —
возвращает `defaultLanguage`, который берётся из переменной окружения
`DEFAULT_LANGUAGE` (`config.ts:20-26`, `packages/env/src/index.ts:485-489`,
по умолчанию `en`).

**Для завода это важно:** поставив `DEFAULT_LANGUAGE=ru` в окружении, вы
получаете русский интерфейс для всех по умолчанию, без настройки у каждого
пользователя.

Переключение языка пользователем:

- UI — меню под аватаром: `apps/erp/app/components/AvatarMenu.tsx:179-215`,
  подменю «Language» со списком эндонимов (`Русский`).
- POST на `/api/locale` → `apps/erp/app/routes/api+/locale.tsx:13-25` →
  `apps/erp/app/services/locale.server.ts:5-19` ставит куку `locale` на год,
  на общий домен (`getCookieDomain(DOMAIN)`), поэтому ERP и MES на поддоменах
  видят один и тот же выбор.
- Валидатор: `apps/erp/app/modules/account/account.models.ts:26-28`
  (`z.enum(supportedLanguages)`).

**Найденные дыры в выборе языка:**

1. **В MES нет переключателя языка вообще.** В `apps/mes/app` нет ни маршрута
   `api/locale`, ни UI со списком языков (проверено grep'ом по
   `getSortedLanguageSelectOptions` / `/api/locale`). MES читает ту же куку,
   но поставить её можно только из ERP. Для цеха, где оператор в ERP может
   вообще не заходить, это означает: язык терминала настраивает не оператор.
2. **Форма выбора языка в профиле мертва.** Компонент
   `apps/erp/app/modules/account/ui/Profile/ProfileLanguageForm.tsx` шлёт
   `intent=locale` на `path.to.profile`, но в
   `apps/erp/app/routes/x+/account+/profile.tsx:38-103` обрабатываются только
   `intent === "about"` и `intent === "photo"`, а сама форма на странице не
   рендерится (`profile.tsx:110` рендерит только `<ProfileForm>`). Мёртвый код.
3. **Язык не хранится в БД.** Только кука. Чистка куки / другой браузер /
   другое устройство — язык сбросится на `DEFAULT_LANGUAGE`. В миграциях
   `packages/database/supabase/migrations/*.sql` колонки `locale` нет.

### 2.5 Как добавить строку / язык

```bash
# добавили <Trans>…</Trans> или t`…` в коде
pnpm lingui:extract        # обновить .po всех языков
pnpm translate             # LLM-дозаполнение пустых msgstr (linguito --llm)
pnpm lingui:clean          # убрать шум заголовков
# .po коммитим, .mjs — нет, они сгенерируются при сборке
```

Новый язык: код добавить в `lingui.config.js` **и** в `supportedLanguages` +
`languageNativeLabels` в `packages/locale/src/config.ts`, затем extract.

CI-гейт: `.github/workflows/check.yml:93-118` — отдельная джоба `Lingui`,
гоняет `pnpm run lingui:check` (extract + compile). То есть забытая разметка
или сломанный ICU-синтаксис ловятся на PR.

### 2.6 Инструменты качества перевода (свои, не из коробки Lingui)

В репозитории собран довольно зрелый конвейер:

| Команда | Что делает |
|---|---|
| `.claude/skills/translate/SKILL.md` | Регламент: разбить пустые строки на чанки, приложить утверждённые термины, раздать дешёвым субагентам, детерминированно смержить |
| `node .claude/skills/translate/scripts/glossary-lookup.mjs --term Job --locale ru` | Какой утверждён перевод термина |
| `node .claude/skills/translate/scripts/check-glossary.mjs --locale ru` | Какие переводы расходятся с глоссарием |
| `node .claude/skills/translate/scripts/reset-violations.mjs --locale ru` | Обнулить расходящиеся переводы, чтобы их перевели заново |
| `pnpm exec linguito check` | Проверка, что пустых `msgstr` не осталось |

### 2.7 Что такое glossary и как он влияет на термины

**`packages/locale/locales/glossary.json`** — 449 доменных терминов, у каждого:
`term` (английский), `category`, `context` (что слово значит именно в Carbon),
`translations` по 12 языкам, иногда `ambiguity` (89 терминов),
`englishVariants`, `seeAlso`.

Правила из `_readme` файла (важные для понимания подхода):

- `baseFormRule`: в глоссарии лежит **базовая (словарная) форма**, это выбор
  слова, а не текст для вставки. Переводчик обязан просклонять: «заказ →
  заказа». Чекер сравнивает по основе слова.
- `howToDecideATerm`: брать слово, которым пользуется ERP на этом рынке, а не
  словарное. Прямо перечислены ловушки: *Job* — сменное задание/произв. заказ,
  а не «работа»; *Receipt* — поступление товара, а не квитанция; *Operation* —
  шаг маршрута, а не «действие».
- `doNotSeedFromExistingTranslations`: **не брать термин из уже готовых `.po`**
  — они переводились без контекста, и большинство часто неверно.
- `ambiguityRule`: у термина с пометкой `ambiguity` утверждённый перевод
  применяется только к доменному смыслу.
- `doNotTranslate`: `Carbon, PDF, CSV, QR, API, URL, ID, SKU, EAN, UPC, CAD,
  STEP, GLB, SSO, MFA, JSON, XML`.

Влияние на термины — **косвенное, но сильное**: глоссарий не подставляется в
рантайме, он (а) раздаётся переводчику/модели как обязательный словарь при
заполнении пустых строк, (б) служит эталоном для `check-glossary.mjs`.
Русская колонка заполнена на **449/449 = 100 %**.

**Второй глоссарий** — `packages/glossary/src/terms.ts` (427 записей) — это
рантайм: `term` и `definition` объявлены через `msg` (`terms.ts:25`), поэтому
попадают в `.po` и переводятся; `packages/react/src/LabelWithHelp.tsx:36-38`
достаёт запись и рендерит `i18n._(entry.term)` / `i18n._(entry.definition)` в
всплывающей подсказке рядом с полем формы. Русские определения в каталоге
есть — например, `packages/locale/locales/ru/erp.po:3324`.

### 2.8 Даты, числа, валюта

Переводятся не через Lingui, а через `Intl` + `useLocale()` из
`@react-aria/i18n`:

- `apps/erp/app/hooks/useDateFormatter.tsx:11`, `useCurrencyFormatter.tsx:56`,
  `usePercentFormatter.tsx`;
- `packages/utils/src/date.ts:32-36, 146-151, 212` — кэшированные
  `Intl.DateTimeFormat`/`NumberFormat`, дефолт `en-US` (`date.ts:9`), если
  локаль не передана.

Для `ru-RU` это даст `16.09.2026` и `1 234,56` автоматически. Валюта берётся
из настроек компании (`company.baseCurrencyCode`,
`useCurrencyFormatter.tsx:55`), то есть рубль настраивается, а не хардкожен.

## 3. Состояние русской локали

### 3.1 Цифры

| Файл | Строк (msgid) | Пусто | Заполнено | Размер |
|---|---|---|---|---|
| `packages/locale/locales/ru/erp.po` | 6 486 | 31 | **99,5 %** | 820 КБ, 19 824 строки текста |
| `packages/locale/locales/ru/mes.po` | 509 | 0 | **100 %** | 47 КБ, 1 604 строки |

(В задаче фигурировало «6487 строк» — это число `msgid` в `erp.po` вместе с
служебным заголовком, а не число строк файла.)

Все 12 целевых языков заполнены одинаково (31-33 пустых в `erp.po`).
`nl` (голландский) — сирота: файлы есть, в `lingui.config.js` и
`supportedLanguages` языка нет, каталог устарел (2 735 строк, все пустые).

Непереведённые 31 строка — это самая свежая фича (возвраты/RMA):
`Purchase Return`, `Sales Return`, `Batches to return`, `Add from receipt`…
То есть **новая функциональность выходит по-английски и догоняется переводом
позже**. При отсутствии перевода Lingui подставит английский оригинал
(`fallbackLocales.default: "en"`), пустого экрана не будет.

Английских «хвостов» внутри русских строк почти нет: из 6 485 строк
только ~15 содержат непереведённые английские слова (`Setup Map`,
`Configured`, `Single Sign-On`, `Linear issue`, `Otherwise`); ещё 25 строк
совпадают с оригиналом законно (`PDF`, `URL`, `AQL`, `SSO/SAML`, `Stripe`).

### 3.2 Что говорит собственный чекер репозитория

```
$ node .claude/skills/translate/scripts/check-glossary.mjs --locale ru
Glossary: 449 terms
  ru: 449/449 terms approved (100%)
Checked 4903 translated strings containing a glossary term.
Violations: 304 enforced, 1154 advisory
```

**304 строгих расхождения** между каталогом и утверждённым глоссарием.
Топ по терминам: `Invoice` 62, `Cost` 23, `Scan` 15, `Contact` 13,
`Ability` 11, `Release` 11, `Demand` 10, `Sales Invoice` 9,
`Purchase Invoice` 8, `Customer` 7, `Jobs` 6, `Purchase Order` 5,
`Sales Order` 5, `Journal` 4.

Регламент `.ai/plans/2026-08-27-translation-consistency-runbook.md:170` прямо
перечисляет русский в очереди на починку с бэклогом 2 155 (замер до
доработки чекера). Починен только китайский (`3c9315ce3`). То есть
**русская локаль в апстриме официально считается непровычитанной**.

Важная оговорка: часть «нарушений» — ошибка глоссария, а не перевода.
62 нарушения по `Invoice` возникают потому, что каталог пишет «счёт»
(правильно), а глоссарий требует «Счет-фактура» (для РФ — неправильно).
Если запустить починку как есть, инструмент **испортит** 62 хорошие строки.

### 3.3 Множественные числа (ICU plurals) — системная ошибка для русского

В `ru/erp.po` 12 сообщений с ICU-плюралами, и **во всех 12** есть только
ветки `one` и `other`, формы `few` нет:

```
packages/locale/locales/ru/erp.po:269
msgid  "{excluded, plural, one {# row excluded} other {# rows excluded}}"
msgstr "{excluded, plural, one {# строка исключена} other {# строк исключено}}"
```

Русский требует трёх форм (`one` / `few` / `many`). `Intl.PluralRules("ru")`
для 2, 3, 4 вернёт `few`, ветки нет → падение в `other` → пользователь видит
**«2 строк исключено»** вместо «2 строки исключены». Для 5+ случайно верно.

Заголовок `Plural-Forms:` в `ru/erp.po:13` пустой — Lingui его не использует,
но это же показывает, что файл никто не готовил под русский.

Правильный вид:
`{excluded, plural, one {# строка исключена} few {# строки исключены} many {# строк исключено} other {# строки исключено}}`

Объём правки маленький (12 строк в ERP), но без неё числа в интерфейсе
выглядят как машинный перевод.

### 3.4 Серверные сообщения не переводятся вообще — главная дыра

В `lingui.config.js` стоит `exclude: ["**/*.server.*", ...]`, а сообщения
успеха/ошибки в маршрутах пишутся голыми строками, без макроса:

```
apps/erp/app/routes/x+/account+/profile.tsx:70
  return data({}, await flash(request, success("Updated profile")));
apps/erp/app/routes/x+/account+/profile.tsx:66
  error(updateAccount.error, "Failed to update profile")
```

Измерено по коду:

| Что | Количество |
|---|---|
| Вызовов `success("…")` в `apps/erp/app` | 514 |
| Уникальных текстов `success()` | 471, из них есть в `ru/erp.po` — **8** |
| Уникальных текстов `error(…, "…")` (ERP + MES) | 1 221 |
| Литералов `toast.success/error("…")` в компонентах | 24 |

Итого **порядка 1 700 уникальных сообщений** — все всплывающие уведомления
после сохранения, удаления, проведения, импорта, любой ошибки — **останутся
английскими** в русском интерфейсе. Это самый заметный для пользователя
пробел: экран русский, а после каждого «Сохранить» всплывает
*«Updated purchase order»*.

Также **не входят в извлечение**: `packages/documents` (генерация PDF —
печатные формы КП, заказов, счетов). В конфиге есть только
`packages/printing/src/ui`. То есть печатные документы для клиента,
скорее всего, останутся английскими — это отдельная задача.

время»). Для оператора это выглядит как разные системы.

## 5. Оценка объёма русификации

| Работа | Объём | Чем делается |
|---|---|---|
| Вычитка терминологии `ru/erp.po` + `ru/mes.po` | ~7 000 строк, из них реально трогать ~300-600 | `check-glossary.mjs` → `reset-violations.mjs` → перезалив; либо ручная правка `.po` в Poedit/Weblate |
| Исправление русской колонки `glossary.json` | ~30-40 терминов из 449 (Invoice, Journal, Revision, Change Order, Labor, Backflush, Method, Batch) | Правка JSON, **до** запуска починки — иначе инструмент размножит неверный термин |
| Множественные числа | 12 строк в ERP | Руками добавить ветку `few` |
| Перевод серверных сообщений | **~1 700 строк + правка кода** (обернуть `success()/error()` в макросы или вынести в каталог) | Это разработка, не перевод. Самая дорогая часть |
| Перевод печатных форм (`packages/documents`) | Не измерено, пакет вне конфига извлечения | Добавить в `lingui.config.js` + разметить |
| Переключатель языка в MES | Нет вообще | Разработка: маршрут `api/locale` + UI, по образцу `AvatarMenu.tsx:179-215` |
| Хранение языка в профиле (БД) | Нет | Разработка: колонка + чтение в loader; сейчас только кука |
| Локаль по умолчанию = ru | 1 переменная окружения | `DEFAULT_LANGUAGE=ru` |

Что **не** входит в локализацию, но всплывёт рядом: НДС и первичка РФ
(УПД, ТОРГ-12, счёт-фактура как документ), печатные формы по ГОСТ,
интеграция с 1С/ЭДО — в Carbon этого нет, это отдельный пласт доработки.

## 6. Чего в коде НЕТ (проверено, не додумано)

- Нет хранения выбранного языка в БД — только кука `locale`.
- Нет переключателя языка в MES.
- Нет русской локализации печатных PDF-документов (`packages/documents` не
  извлекается).
- Нет перевода серверных flash/toast-сообщений (исключены `**/*.server.*` +
  не размечены макросами в маршрутах).
- Нет формы `few` в ICU-плюралах русского каталога.
- Нет локализации сайта документации (`docs/`) и `apps/academy` — `.po` для
  них не существует.
- Нет автоматической проверки качества перевода на стороне CI: джоба `Lingui`
  проверяет только извлечение/компиляцию, `check-glossary.mjs` в CI не вызывается.
