# Проверка схемы «длина куска = складское количество» на Odoo 19

Прогон 18.09.2026 на стенде `:8084` (Odoo 19.0 Community + RuOdoo).
Проверялась схема учёта металлопроката: **один товар на типоразмер, базовая
единица — метр, каждый физический кусок — партия, количество партии равно его
длине**. Обрезок — та же номенклатура на складе деловых остатков.

Скрипты выполняются через `odoo shell`, менять ничего в коде Odoo не требуется:

```bash
ssh factory
cd /opt/experiments/odoo
docker compose cp 1-setup.py odoo:/tmp/
docker compose exec -T odoo sh -c 'cat /tmp/1-setup.py | odoo shell -d odoo \
  --no-http -c /etc/odoo/odoo.conf --db_host=db --db_user=odoo --db_password=$PASSWORD'
```

## Поправки к предварительному разбору

Прогон опроверг три ожидания — два в худшую сторону, одно в лучшую.

1. **`stock.valuation.layer` в Odoo 19 не существует.** Механизм оценки
   переработан: стоимость лежит прямо на остатке — `stock.quant.value`, плюс
   журнал `product.value` с полем `lot_id`. Для нашей задачи это удобнее:
   стоимость и так хранится в разрезе партии.

2. **Режим оценки по умолчанию — `periodic` («при закрытии»), и в нём стоимость
   партии не считается вовсе** (все нули). Нужен `real_time` («Perpetual, at
   invoicing») на категории товара. Вариантов в Odoo 19 всего два, `manual`
   больше нет.

3. **Цена в документе прихода стоимость не формирует.** `price_unit` на
   `stock.move` игнорируется: стоимость берётся из себестоимости товара
   (`standard_price`) или приходит со счётом поставщика. Пока себестоимость
   нулевая, приёмка кладёт на склад металл ценой ноль — молча.

4. **Резерв обрезка короче метра работает штатно.** Разбор предсказывал, что
   `lot_ids` выделяет минимум одну базовую единицу и потребуется сторонний
   `stock_restrict_lot`. Проверка показала обратное: 0.790 м резервируется
   обычным полем. Из плана уходит 2 дня и одна внешняя зависимость.

## Что НЕ проверено

- Контур листа: позиции «Лист 4 мм» и «Лист 8 мм» (м², 31.4 и 62.8 кг/м²)
  заведены, но раскрой и остатки карт не прогонялись.
- Поведение при среднем методе себестоимости (проверен только FIFO).
- Landed cost по партиям, производительность на 300+ бирках.
- Приёмка «одна бирка на пачку» — режим, который нужен ПМК Парк, потому что на
  приёмке всегда 2-3 стандартных размера и сотни хлыстов.
- Штатный генератор партий при приёмке: создаёт ли он куски разной длины за один
  проход, или мастер приёмки придётся писать.
