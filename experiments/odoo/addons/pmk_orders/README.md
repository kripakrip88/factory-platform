# pmk_orders — счета покупателям и «Заказы в работе»

Разбор удобства: шаг З-2 (08.10.2026, карточка 2) и шаг З-9 (09.10.2026,
карточка 9) проекта «Заказ от заявки до цеха». КП и счёт для завода — один
документ.

## Жизнь счёта (шаг З-9)

Решения Антона 09.10.2026: «Счёт как таковой создаётся на этапе расчёта,
возможно меняется или дополняется, и только когда окончательно сформировали,
прописали условия, согласовали с руководителем» — отправляется. «Сначала
отправили, а потом перетащили сделку. Автоотправки не нужны, перенос либо
руками, либо после нажатия на кнопку «Отправить КП»».

```
«Счёт» в расчёте ─▶ Черновик ─ «На согласование» ─▶ На согласовании ─ «Согласовано» ─▶ Согласован
                       ▲                                 │ «Вернуть на доработку»
                       └─────────────────────────────────┘
«Отправить КП» / сделку перенесли в «КП отправлено» руками ─▶ Отправлен
«Выиграно» / «Оплата пришла — в работу» ─▶ В работе (оплачен)      «Проиграно» ─▶ Отменён
```

| Что сделали | Что со счётом |
|---|---|
| «Счёт» в расчёте (контурная, рядом с «Отправить КП») | Счёта нет — черновик из этого расчёта (клиент, наша организация, сделка, изделия с ценой строками). Есть черновик — обновляется; черновик другого расчёта сделки — переключается на этот (новый счёт не заводится). Отправлен — открывается с подсказкой «изменения войдут как ред. N при «Отправить КП»». Отменён у сделки в работе — снова черновик. Нет сделки или клиента — ошибка словами. |
| Правка и сохранение расчёта | Строки-изделия черновика пересобираются сами (без редакций), услуги не трогаются. Согласованный черновик — снова «Черновик» с заметкой. Отправленный не меняется: плашка «Расчёт изменился после отправки: ред. N при «Отправить КП»». |
| «На согласование» | Руководителю — задача «Согласовать счёт» (без письма). «Согласовано» и «Вернуть на доработку» (с комментарием — задача «Доработать счёт» менеджеру) — только группе «Руководитель: согласует счета» (в ней admin). Правка счёта после «Согласован» — снова «Черновик». |
| «Отправить КП» (письмо ушло людям клиента) | Счёт этого расчёта — «Отправлен»: черновик (переключённый на отправленный расчёт, если был из другого); нет черновика — заводится и сразу «Отправлен». Уже отправлен и расчёт поменялся — новая редакция. Сделка — «КП отправлено». Не согласован — отправка не блокируется, на счёте и в окне письма видно «не согласован». |
| Сделку перенесли в «КП отправлено» руками | КП ушло вне системы: черновик — «Отправлен» с заметкой. Счёта нет — **не заводится**, в ленте сделки заметка. Отправленный — не меняется (заметка, если расчёт изменился). |
| «Выиграно» (предоплата / гарантийное письмо) | Счёт подтверждается («В работе (оплачен)»), появляется **ровно одна** строка «Заказов в работе» в «Очереди». Счёта нет — строка без счёта и заметка (счёт не заводится). |
| «Оплата пришла — в работу» в счёте (у отправленного; у черновика — в «Убранном») | То же, что «Выиграно»: сделка становится выигранной. Задачи «Согласовать» / «Доработать» закрываются, «На согласовании» → без отметки. |
| «Новая редакция» у отправленного счёта (ссылка над строками) | Условия, услуги и дата отправленного закрыты — так их видел клиент. Нужно поменять — снимок прежней редакции (только для чтения), счёт снова черновик «ред. N+1», дальше как обычно. |
| «Проиграно» | Счёт отменяется, задачи согласования снимаются. Строка планировщика остаётся. |

Писем клиенту модуль не шлёт ни одного: письмо уходит только по кнопке
«Отправить» в окне «Отправить КП». Технически состояния — штатные `draft` /
`sent` / `sale` / `cancel` (на них опираются ядро, планировщик, pmk_tech),
согласование — своё поле `pmk_approval`, статус словами — `pmk_status`.

## Счёт покупателю

- **Строки-изделия** — изделия расчёта по отдельности: служебный товар-услуга
  «Изготовление металлоконструкций», описание = название изделия, количество,
  «шт», цена клиенту за штуку. Строка помнит изделие (`pmk_spec_product_id`) и
  что она из расчёта (`pmk_from_spec`). В счёте они **только для чтения** (вид
  и сервер: правка названия, количества, цены и удаление — ошибка «меняют в
  расчёте»). Кнопка «Изменить в расчёте» открывает расчёт.
- **Услуги** — «Добавить услугу» под строками (товар «Услуга»): доставка,
  монтаж, разгрузка — описание, количество, цена правятся в черновике; новая
  редакция их переносит; в подпись «расчёт изменился» не входят. Цены закупки
  у услуги нет (перепродажа отложена). В КП (печать расчёта) услуг и условий
  нет до шага 62 — окно «Отправить КП» говорит об этом жёлтой плашкой.
- **Условия** (под строками): срок оплаты (список ядра), оплата своими
  словами, срок изготовления (раб. дней + с момента оплаты / согласования
  чертежей / даты счёта), доставка или самовывоз и адрес, прочие условия.
  Для печати (шаг 62) — готовые строки `pmk_lead_text` («20 раб. дней с
  момента оплаты») и `pmk_delivery_text` («Доставка: …» / «Самовывоз»).
  Условия хранятся в снимке прежней редакции.
- **Итог** — «Итого» и строка налога как в КП: «в том числе НДС 22%: …» или
  «Без НДС (УСН)» (`pmk_tax_text`, режим организации на дату счёта).
- **Налог** — режим нашей организации на дату счёта (`pmk_org`). Цены ВСЕГДА с
  НДС: компания Odoo — «цены включают налог», сумма счёта = сумме КП. Группа
  налога режима — «НДС 22%» (до шага З-9 — «Налог 15%» плана счетов,
  `pmk_org` 19.0.1.2.0).
- **Шапка**: клиент, наша организация, дата счёта, сделка; расчёт — кнопкой
  «Расчёт», редакция — «ред. N» у номера. Остальное («Другая информация»,
  адреса, шаблон КП, срок действия, прайс-лист, штатные итоги, колонки
  «Товар», «Налоги», «Отгружено», «Выставлен счёт», «Налог не включён»,
  «Добавить товар / раздел / заметку», «Каталог») — в «Убранном» (`Деньги` /
  `Склад`), список — `docs/disabled-features.md`, шаг З-9.
- **«Новое» и «Дублировать»** убраны у формы, списка и канбана: счёт
  рождается кнопкой «Счёт» в расчёте или «Отправить КП».
- Права: продавец без «Проектов» видит, правит и заводит строки
  планировщика (правило `rule_orders_rows_sales`), удалять не может.
- Номер — «СЧ-00001» (хук установки, пока заказов клиента нет).

## Редакции

Действующий счёт — та же запись (номер, ссылки из сделки и планировщика
живы), `pmk_revision` растёт. Прежняя редакция — снимок: отдельный
`sale.order` с тем же номером, собранный явными значениями (с условиями),
отменён, заблокирован, без сделки, со ссылкой `pmk_revision_of_id` на
действующий. Правка содержания, смена состояния и удаление снимка — ошибкой.
Редакция появляется только при «Отправить КП» уже отправленного счёта
(или кнопкой «Счёт» у отменённого, который уходил клиенту); черновик
редакций не даёт. Согласование новой редакции сбрасывается.

## Планировщик «Заказы в работе»

Штатный проект (данные модуля, noupdate) с этапами Очередь / Разработка
чертежей / Ждём металл / В работе / Пауза / Готово к отгрузке / Отгружено
(свёрнут). Строка — задача проекта с полями Excel-планировщика Антона
(`pmk_*`). Виды — список как Excel, канбан по этапам, компактная форма.
Меню: «Продажи → Заказы в работе» и «Проекты → Заказы в работе». Сумма
строки — из счёта; без счёта (будущий импорт из Excel, карточка 3) —
руками. «№ счёта», сумма и дата оплаты — пока руками (потом МойСклад).

## Установка

```
INSTALL="pmk_orders base_automation" sh deploy.sh
```

«Правила автоматизации» (`base_automation`) ставятся тем же прогоном, но не
зависимостью: они тянут `sms`, и удаление «SMS» каскадом снесло бы этот
модуль вместе с планировщиком. Ничего в них не настроено.

Шаг З-9 — обновление `pmk_orders` (19.0.1.1.0: миграция ставит дату
«Отправлен» уже отправленным и делает цену строк-изделий «ручной» для ядра —
technical_price_unit = 0, иначе смена одного количества сбрасывала цену в
0 ₽), `pmk_org` (19.0.1.2.0: группа налога, её счета — из прежней),
`pmk_theme` (слова, скрытые узлы, стили, пункты ⚙ «Отправить электронное
письмо» / «Отметить … отправленным» / «Создать заказ» — в «Убранном»),
`pmk_tech` (кнопка «Счёт» у технического расчёта спрятана, «Технический
расчёт» у черновика счёта — нет), `pmk_laser` (поле «Заказ» без «Создать…»).
Счёт из файла (вставка или перетаскивание PDF в список счетов) — ошибкой.

⚠️ **Модуль не удалять**: удаление сотрёт проект «Заказы в работе» со всеми
строками и поля счетов (редакции, связь с расчётом, условия, согласование).

Список спрятанного и как вернуть — `docs/disabled-features.md`, шаги З-2 и
З-9. Тесты — `tests/` (одноразовая база, см. `tests/__init__.py`).
