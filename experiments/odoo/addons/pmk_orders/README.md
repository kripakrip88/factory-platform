# pmk_orders — счета покупателям и «Заказы в работе»

Разбор удобства, шаг З-2 (08.10.2026), карточка 2 проекта «Заказ от заявки
до цеха». Решения Антона 07–08.10.2026: КП и счёт для завода — один документ.

## Что делает

| Событие на сделке | Что происходит |
|---|---|
| «КП отправлено» (кнопка «Отправить КП» в расчёте или перетаскивание в воронке) | Из расчёта выставляется «Счёт покупателю» (штатный заказ клиента `sale.order`) в состоянии «Выставлен, ждём оплату». Расчёт — тот, КП которого ушло. При перетаскивании (и при «Выиграно»): счёт уже есть — тот же расчёт, по которому он выставлен (если расчёт ещё этой сделки); счёта нет — главный расчёт сделки. Новый вариант расчёта счёт сам не переписывает: выставить по нему — «Отправить КП» из него. |
| Расчёт поменяли и снова «КП отправлено» | Не новый счёт, а **новая редакция** того же: номер тот же, «ред. 2», «ред. 3». Прежняя редакция сохраняется только для чтения (вкладка «Редакции» в счёте). |
| «Выиграно» (предоплата или гарантийное письмо) | Счёт подтверждается («В работе (оплачен)»), появляется **ровно одна** строка планировщика «Заказы в работе» в этапе «Очередь». |
| «Оплата пришла — в работу» в самом счёте | То же, что «Выиграно»: сделка становится выигранной. |
| «Проиграно» | Действующий счёт отменяется. Строка планировщика, если была, остаётся. |

Ничего не блокирует: нет расчёта, цены клиенту или клиента — счёта нет,
стадия меняется как обычно, в ленте сделки заметка, почему. Изделия без цены
в счёт не идут (как и в печать КП) и перечислены в заметке.

## Счёт покупателю

- Строки — изделия расчёта по отдельности: служебный товар-услуга
  «Изготовление металлоконструкций» (без склада и отгрузок), описание =
  название изделия, количество, «шт», цена клиенту за штуку. Строка помнит
  изделие (`pmk_spec_product_id`) и что она из расчёта (`pmk_from_spec`).
  Ручные строки (доставка, скидка) редакция не трогает.
- Налог — режим нашей организации на дату счёта (`pmk_org`). Цены ВСЕГДА с
  НДС (решение Антона 08.10.2026): компания Odoo — «цены включают налог»
  (`pmk_org` 19.0.1.1.0), налоги следуют ей. Сумма счёта = сумме КП:
  150 ₽ от организации на НДС 22% — 150, в т. ч. НДС 27,05; на УСН — 150,
  «Без НДС». Смена организации меняет налог строки, не цену. Налоговую
  позицию для режимов не используем: она пересчитала бы 150 → 122,95.
- Права: продавец без «Проектов» видит, правит и заводит строки
  планировщика (правило `rule_orders_rows_sales`), удалять не может.
- Писем клиенту нет: выставление и подтверждение идут без отправки;
  «Отправить» и «Предпросмотр» в счёте спрятаны (КП уходит из расчёта).
- Номер — «СЧ-00001» (хук установки, пока заказов клиента нет).

## Редакции

Действующий счёт — та же запись (номер, ссылки из сделки и планировщика
живы), `pmk_revision` растёт. Прежняя редакция — снимок: отдельный
`sale.order` с тем же номером, собранный явными значениями, отменён,
заблокирован, без сделки, со ссылкой `pmk_revision_of_id` на действующий.
Правка содержания, смена состояния и удаление снимка — ошибкой.

## Планировщик «Заказы в работе»

Штатный проект (данные модуля, noupdate) с этапами Очередь / Разработка
чертежей / Ждём металл / В работе / Пауза / Готово к отгрузке / Отгружено
(свёрнут). Строка — задача проекта с полями Excel-планировщика Антона
(`pmk_*`). Виды — список как Excel, канбан по этапам, компактная форма.
Меню: «Продажи → Заказы в работе» и «Проекты → Заказы в работе». Сумма
строки — из счёта; без счёта (будущий импорт из Excel, карточка 3) —
руками. «№ счёта», сумма и дата оплаты — пока руками (потом МойСклад).

## Установка

```
INSTALL="pmk_orders base_automation" sh deploy.sh
```

«Правила автоматизации» (`base_automation`) ставятся тем же прогоном, но не
зависимостью: они тянут `sms`, и удаление «SMS» каскадом снесло бы этот
модуль вместе с планировщиком. Ничего в них не настроено.

⚠️ **Модуль не удалять**: удаление сотрёт проект «Заказы в работе» со всеми
строками и поля счетов (редакции, связь с расчётом).

Список спрятанного и как вернуть — `docs/disabled-features.md`, шаг З-2.
Тесты — `tests/` (одноразовая база, см. `tests/__init__.py`).
