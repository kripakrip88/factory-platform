# pmk_vpn — личные ключи VPN сотрудникам через бота

**Статус:** 28.10.2026 — модуль написан, не выложен. Выкладку ведёт отдельный
чат: сначала копия :8099, затем боевой по фразе Антона.

## Решения Антона (28.10.2026)

* Ключ получает **каждый, у кого привязан Телеграм**. Просить и подтверждать
  не нужно: ключ приходит уведомлением с инструкцией.
* У каждого **свой QR-код**, не больше **3 устройств** одновременно.
* Личный ключ Антона (он, жена, родители) — отдельный, без лимита. Модуль его
  не трогает.

## Как выглядит

Сотруднику приходят от бота:

1. QR-код «Основной ключ» и ссылка под ним (нажать — скопируется);
2. QR-код «Запасной ключ» (XHTTP — если основной режет провайдер);
3. инструкция: V2Box (iPhone), v2rayNG (Android), Hiddify (компьютер); лимит
   3 устройства; «не пересылайте».

В меню бота у сотрудника кнопка **«🔐 VPN»** — прислать ключ ещё раз. У
администратора есть ещё **«🔐 VPN: сотрудники»**: кто в сети, трафик за день и
за месяц, кнопки «Отключить» и «Включить».

Odoo → **Настройки → VPN-ключи**: список, переключатель «Доступ», «Отправить
ещё раз», «Новый ключ» (старый перестаёт работать в течение минуты). Над
списком — кнопка **«Разослать ключи»**.

Тревога администратору (раз в сутки на человека): ключ сейчас на большем
числе устройств, чем можно. В тревоге кнопки «🔄 Новый ключ» и «⛔ Отключить».

## Устройство

* `models/vpn_key.py` — ключ (строка на человека), рассылка, приём с сервера.
* `models/vpn_traffic.py` — трафик по дням (байты во Float: int4 переполнится).
* `models/bot.py` — кнопки бота; наследует `pmk.telegram.bot`.
* `models/links.py` — ссылки `vless://` без Odoo (проверяются и в `experiments/vpn/tests`).
* `controllers/sync.py` — `POST /pmk_vpn/sync`, секрет в `X-Pmk-Vpn-Token`.
* Крон «VPN: отправить ключи» — раз в 5 минут, пачкой по 10.

**Нагрузка (правило 11).** Odoo не ждёт сеть. QR-код делается локально
(reportlab), VPN-сервер приходит сам раз в минуту с маленьким JSON. Трафик
пишется одним `INSERT … ON CONFLICT`. Частые записи идут в `pmk_vpn_key`, а
не в `res.users`, чтобы не сбрасывать кэши.

**Безопасность.** На VPN-сервере (за границей) нет ФИО: ключ называется
`u<номер пользователя>`. Адреса устройств Odoo не хранит, только их число и
отключённые лишние.

Кому ключ работает: пользователь не в архиве, не портальный, с Telegram ID и с
включённым «Доступом». Уволили (архив) — ключ отключается сам в течение минуты.

## Выкладка (для чата выкладки)

1. Поставить модуль (`-i pmk_vpn`), прогнать тесты: `--test-tags /pmk_vpn`.
   Они идут без сети, Телеграм подставной.
2. Системный параметр `pmk_vpn.sync_token` — секрет из
   `experiments/vpn/install.sh` (печатается в конце установки на VPN-сервере).
3. На VPN-сервере — `experiments/vpn/README.md`, раздел «Установка».
4. **После установки никому ничего не уходит**, пока не нажата «Разослать
   ключи». Это рассылка сотрудникам — только по слову Антона.

Проверка на копии :8099. Синхронизацию на копию не направлять: VPN-сервер
один, и он смотрит в боевой Odoo. Чтобы увидеть QR-коды на копии, параметры
сервера можно вписать руками:

```python
env["ir.config_parameter"].set_param("pmk_vpn.server", '{"host": "31.77.141.89", "sni": "mediagenstvo.ru", "pbk": "<pbk>", "sid": "<sid>", "port_tcp": 443, "port_xhttp": 8443, "xhttp_path": "<path>"}')
```

`pbk`, `sid` и `path` взять из `/root/vpn-link.txt` и `/root/vpn-link-2.txt`
на VPN-сервере (`ssh vpn`).
