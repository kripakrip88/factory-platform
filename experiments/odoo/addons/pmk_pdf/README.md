# pmk_pdf — работа с PDF внутри документа

Открыть приложенные к документу PDF, посмотреть страницы, повернуть, удалить,
переставить, склеить несколько файлов в один, разрезать на части — и положить
результат обратно в тот же документ.

## Почему свой модуль, а не готовый сервис

Рассматривали два (сентябрь 2026).

**PDFCraft** — встроить нельзя технически, три независимые причины:
отдаёт `X-Frame-Options: SAMEORIGIN` во всех конфигах деплоя; не имеет никакого
программного интерфейса (ни API, ни postMessage, ни параметров URL), то есть
файл из вложения не передать и результат не забрать; требует cross-origin
isolation (COOP/COEP) для многопоточного WebAssembly, а внутри iframe эта
изоляция теряется, если те же заголовки не выставит страница-хозяин — что
поломает на ней всё стороннее.

**Stirling-PDF** — встроить можно, REST API есть, и вся работа с PDF в нём под
MIT (платная часть — учётки, биллинг, кластер, аудит; лимит в 5 пользователей
захардкожен, но касается только встроенных учёток Stirling). Отказались не
из-за лицензии, а из-за веса: образ 1,07 ГБ, по документации 2 ГБ памяти, а для
команды 1–10 человек рекомендуют 4 ГБ; облегчённый образ на 336 МБ не содержит
ни OCR, ни LibreOffice — то есть именно того, ради чего его ставят. Память там
пропорциональна файлу: PDF на 50 МБ со сложной графикой раздувается при
обработке до 200–500 МБ, а чертежи как раз такие.

Всё, что нужно для перечисленных задач, уже есть в Odoo:

| Что | Чем | Ставить |
|---|---|---|
| Показ страниц | pdf.js — `web/static/lib/pdfjs` | уже есть |
| Сборка файла | PyPDF2 2.12.1 | уже есть |
| Текст из цифровых PDF | pdfminer | уже есть (на будущее) |

## Устройство

Одна операция вместо пяти: **собери документ из вот этих страниц, в таком
порядке, с такими поворотами**. Через неё выражается всё — склейка, разрезание,
удаление, поворот. Меньше кода, и нечему разойтись между собой.

- Браузер (`static/src/js/pdf_editor.js`) показывает страницы и собирает план.
  Отрисовка ленивая: рисуется то, что видно на экране.
- Сервер (`models/pdf_job.py`) собирает файл по плану через PyPDF2.
- План приходит из браузера, поэтому проверяется весь: права на исходные
  вложения, права на запись в документ, границы страниц, кратность поворота,
  пределы по числу страниц и файлов. **Ни одного `sudo()`** — проверки доступа
  Odoo работают как обычно.

## Точка входа

Кнопка «Правка PDF» в меню действий документа. Привязка **мягкая**: при
установке модуль смотрит, какие из моделей в `hooks.py` есть в системе, и
привязывается к ним. Поэтому `pmk_pdf` и `pmk_calc` не зависят друг от друга —
калькуляторы работают без редактора, редактор без калькуляторов. Новый документ
добавляется одной строкой в `TARGET_MODELS`.
