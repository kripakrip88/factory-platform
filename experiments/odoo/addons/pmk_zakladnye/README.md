# pmk_zakladnye — закладные изделия МН

«Калькуляторы → Закладные» (рядом с фундаментными болтами). Документ ЗК-00001: сделка
(необязательно), клиент, объект текстом, таблица изделий (таблица Бутика).

## Как вводить

Одна строка — одно изделие, коротко:

| Запись | Что это |
|---|---|
| `мн 201-5 12шт` | МН 201-5, 12 шт |
| `мн 104-1 1200 10шт` | погонное МН 104-1, длина 1200, 10 шт |
| `МН 104-6 L1200` | погонное, длина 1200 |
| `м1-9-7 4шт` | серия 1.400-6/76 |

Ctrl+V — столбик марок из Excel. Марку не понял или серия её не поддерживает — строка жёлтая,
причина под записью. Под таблицей — состав выбранного изделия (как спецификация листа 1)
и картинка первого листа чертежа.

## Что поддержано (v1)

- 1.400-15: семейства A (МН 101–164), B (МН 201–228), C (МН 301–325, кроме 301-1…3) и погонные — 570 марок;
- 1.400-6/76: 249 из 349 (пластина + прямые анкеры ± шайбы). Почему не все — `lib/` README сессии «Закладные МН».

## Кнопки

- **Подготовить чертежи** — PDF (2 листа А3) для изделий без свежего чертежа. Рисует фоновый
  процесс (`worker/`), страница не ждёт; таблица сама подхватит готовое, придёт уведомление.
- **Печать ▾**: все чертежи одним PDF; DXF для лазера (zip по толщинам, количество на весь
  документ в имени `…_12шт`); ведомость металла (Excel).
- **Создать ▾ → Задание на резку** — пластины и шайбы деталями задания (лазер) → «Детали
  к раскрою» → «Раскрой листа». Второй раз — открывает то же задание.

## Устройство

- `lib/` — генератор сессии «Закладные МН» (generate.py, gost_draw.py, iso3d.py). Логика не
  тронута; правки только загрузки: данные из `data/`, PyMuPDF импортируется при первом
  рисовании, шрифт — Liberation Sans Narrow Italic (`PMK_ZK_FONT` переопределяет).
- `tools/catalog.py` — справочник марок (из JSON генератора), разбор короткой записи,
  модель изделия и состав. Odoo использует только модель и массы — PyMuPDF ему не нужен.
- `models/job.py` + `worker/` — очередь чертежей файлами в `<data_dir>/zakladnye`, как
  у раскроя вентзонтов. Процесса нет дольше 2 мин — задание ошибкой с причиной (рисовать
  в Odoo нечем).
- `worker/Dockerfile` — образ `pmk-zk-worker`: python 3.12 + pymupdf 1.26.5 + fonts-liberation,
  пользователь uid 100/gid 101 (как odoo).

## Контейнер

Копия (odoo_stage) — `odoo-stage-zk-worker`:

```
docker build -t pmk-zk-worker:1 /opt/experiments/odoo/dryrun/addons-extra/pmk_zakladnye/worker
docker run -d --name odoo-stage-zk-worker --restart unless-stopped --memory 512m --cpus 1 \
  -e PYTHONDONTWRITEBYTECODE=1 \
  -v /opt/experiments/odoo/dryrun/stage-data:/stage-data \
  -v /opt/experiments/odoo/dryrun/addons-extra:/mnt/third-party:ro \
  pmk-zk-worker:1 /stage-data/zakladnye
```

Боевой — сервис `zk-worker` в `experiments/odoo/docker-compose.yml` (добавляется при выкладке,
по разрешению Антона): тот же образ, том `odoo_data:/var/lib/odoo`, папка модулей только чтение,
512 МБ, 1 ядро.

## Тесты

- Odoo (`tests/test_zk.py`): запись строки, регрессия 786 изделий против `tests/data/index_*.csv`,
  масса против серии (±5 % / ±6 %), DXF читается `sheet_nest.read_dxf`, очередь чертежей,
  задание на резку.
- Чертежи (`tests/check_drawings.py`, где есть PyMuPDF — в образе процесса): 2 листа, ни одна
  линия не проходит через надпись, техтребования в рамке. `--all` — все 786.

```
docker run --rm -v <addons>:/mnt/third-party:ro --entrypoint python3 pmk-zk-worker:1 \
  /mnt/third-party/pmk_zakladnye/tests/check_drawings.py --all
```
