# Geometry2D/data.bin в программах CypCut 6.3 (.lxds): что удалось установить

Кодек: `work/geo_codec.py`. Самопроверка: `python3 -I geo_codec.py samples/*.lxds --json geo_selftest.json`.
Полный вывод лежит в `geo_selftest.txt` и `geo_selftest.json`. Скрипты разведки называются `geo_explore*.py`.
Образцы читаются как zip в памяти. Файлы в `x/` совпадают с членами zip побайтно (5 из 5).

## 0. Итог проверки

| Проверка (все 5 образцов) | Результат |
|---|---|
| `serialize(parse(b)) == b` для всего файла | **5/5, 0 отличающихся байт** |
| Объекты разобраны в типизированную модель, без сырого запаса | 3978/3978 |
| Сборка объектов с нуля функциями `encode_*` из декодированной геометрии | **3978/3978 объектов байт в байт** |
| Сборка всего data.bin с нуля через `build_data_bin` | 5/5 файлов, 0 байт разницы; GeoAddr совпадают с XML |
| `Geometry2D/content.xml`, собранный с нуля | 5/5 байт в байт |
| Контрольная порча модели: x+1 у вершины; лишняя вершина | меняются 1–2 байта; файл растёт на +32, следующие адреса сдвигаются на +32, размер в заголовке пересчитан |
| Бонус: тот же разбор контейнера без типов на Shapes2D/data.bin | 5/5 байт в байт |

Формат одинаков в версиях 6.3.907.8 (m3, m8) и 6.3.907.11 (zonty, m14, m30).

## 1. Контейнер

**Заголовок, 0x0000–0x0FFF**

| Смещение | Поле | Значение |
|---|---|---|
| 0 | сигнатура | `BCMP` |
| 4 | u32 | **длина всего файла**, совпадает в 5/5 |
| 8 | u32 | 1 (версия формата?), в 5/5 |
| 12..0xFFF | — | все нули, 5/5. В модели хранятся сырыми |

**Объект** начинается с адреса 0x1000. Его адрес равен `GeoAddr`.

| Смещение | Поле |
|---|---|
| +0 | `d1 d1 d1 d1` |
| +4 | u32 = 0 (3978/3978) |
| +8 | u32 **длина объекта**: от `d1` до конца `d0d0d0d0` включительно. Выравнивание в длину не входит |
| +12 | u32 = 0 (3978/3978). Возможно, это старшее слово u64-длины |
| +16 | строка класса: `TGks` + тип (`TGksLine` / `TGksCircle` / `TGksLwPolyline`) |
| … | подзаписи. В Geometry2D их ровно **1**, промежутков между ними нет |
| конец−4 | `d0 d0 d0 d0` |

**Подзапись**

| Смещение | Поле |
|---|---|
| +0 | `c1 c1 c1 c1` |
| +4 | u32 версия класса подзаписи. В Geometry2D всегда 1. В Shapes2D встречаются Object=1, Shape=6, Curve=2 |
| +8 | u32 **длина подзаписи**: от `c1` до конца `c0c0c0c0` включительно |
| +12 | u32 = 0 |
| +16 | строка: тип без `TGks` (`Line` / `Circle` / `LwPolyline`) |
| … | полезные данные (раздел 3) |
| конец−4 | `c0 c0 c0 c0` |

**Строка:** `53 00`, затем u16 n, затем n байт ASCII, затем нули. Поле дополняется нулями до длины, кратной 8,
**считая от начала поля**, а не по абсолютному адресу. Это доказано на 1426 строках из Shapes2D: они лежат
по адресам 4 mod 8, и правило «от поля» выполняется 1426/1426, а абсолютное выравнивание не выполняется ни разу.
Метка точки `10 00 02 00` раскладывается так же, как u16 тип + u16 количество: тип 0x10 (точка), 2 double.
Это гипотеза о единой схеме меток. Дополнения после точки нет.

**`TGks`** — префикс имени класса геометрического объекта. Тот же класс и та же строка стоят в начале
объекта в Shapes2D. Один объект делится на два файла: в Geometry2D лежит подзапись с геометрией,
в Shapes2D — Object/Shape/[LeadParam]/Curve.

**Хэндлов и id в Geometry2D нет.** Подзапись «Object» с хэндлом есть только в Shapes2D/data.bin.
Хэндл связан с геометрией только через `GeoAddr` в Shapes2D/content.xml.

**Как размещаются объекты** (5/5 файлов, 3978 объектов):
- объекты идут подряд с 0x1000. Каждый дополнен нулями до кратности 8 (дополнение 0 или 4 байта, всегда нули). Свободных дыр нет, после последнего объекта ничего нет;
- `GeoAddr` = начало объекта (`d1`), 3978/3978. Каждый объект упомянут в XML ровно один раз;
- **порядок в файле = порядок в Shapes2D/content.xml** (5/5). Он же равен порядку контуров в Blocks/content.xml (блок за блоком). В конце идут контуры, которых нет ни в одном блоке: контур листа из Nest2D/Plates и контуры листов раскладок из Results;
- тип в XML (`<Line>`/`<Circle>`/`<LwPolyline>`) = имя класса без `TGks`, 3978/3978;
- размеры с учётом выравнивания: **Line 104, Circle 120, LwPolyline 104 + 32·n**. Размер файла = 4096 + сумма размеров. Например, m14: 4096 + 1410·120 + 2·232 = 173760 ✓.

**Geometry2D/content.xml** = `<?xml version="1.0" encoding="utf-8"?>` + CRLF + `<Geometry2D>` + CRLF + TAB + `<MD5>` + **MD5 файла data.bin заглавными** + `</MD5>` + CRLF + `</Geometry2D>` + CRLF.
Совпадение 5/5. У Shapes2D/content.xml MD5 тоже равен MD5 его data.bin, 5/5.

## 2. Расположение полей (смещения от начала объекта)

| Тип | Поля |
|---|---|
| **Line** (0x68) | 0x38 u32 0x00020010 · 0x3C f64 x1 · 0x44 f64 y1 · 0x4C u32 0x00020010 · 0x50 f64 x2 · 0x58 f64 y2 · 0x60 c0 · 0x64 d0 |
| **Circle** (0x78) | 0x40 u32 0x00020010 · 0x44 f64 cx · 0x4C f64 cy · 0x54 f64 r · 0x5C u32 · 0x60 f64 угол старта · 0x68 8 байт · 0x70 c0 · 0x74 d0 |
| **LwPolyline** (0x64+32n, дополнение 4) | 0x48 f64 start_param · 0x50 u32 flag · 0x54 u32 n · 0x58+32k: {u32 k+1, f64 x, f64 y, f64 bulge, u32} · 0x58+32n u32 · затем c0, d0 |

Z-координат, выдавливания (extrusion), толщины, ширины и высоты нет ни в одном типе. Точки двумерные (метка «2 double»).

## 4. Сборка с нуля: `encode_line`, `encode_circle`, `encode_lwpolyline`

Функции принимают `(handle, геометрия)` и возвращают байты объекта. Хэндл в Geometry2D не записывается.
`build_data_bin([(handle, bytes)…])` возвращает `(data.bin, {handle: GeoAddr})`, `content_xml(data.bin)` возвращает content.xml.
Все неизвестные поля пишутся константами из таблицы раздела 3.

| Режим | Совпало | Отличия |
|---|---|---|
| **полная геометрия**: x, y, bulge с его знаком нуля, flag, start_param, угол | **3978/3978**, 5/5 файлов целиком | нет |
| **«как будет писать генератор»**: flag=1/0, start_param=0, bulge 0 → +0.0, угол π/4 | 2090/3978 | 1888 объектов отличаются **только** в 4 полях; вне их отличий 0 байт |

Причины отличий в режиме генератора, по числу объектов:

| Поле | zonty | m14 | m30 | m3 | m8 |
|---|---|---|---|---|---|
| Circle: угол ≠ точное π/4 (другой квадрант или ошибка округления) | 439 | 985 | – | – | – |
| Lw: flag ≠ 0/1 (биты 2, 4) | 40 | – | 307 | 58 | 11 |
| Lw: bulge −0.0 | 65 | – | 247 | 42 | 11 |
| Lw: start_param ≠ 0 | 7 | – | 13 | 4 | 3 |

Все отличия — это то, что CypCut сам меняет при раскладке: точку старта, совмещённый рез, повороты.
В контурах деталей, импортированных без доработки (блоки CloneForNest в m3/m8), стоят flag=1,
start_param=0, только +0.0. То есть ровно то, что пишет генератор.

## 5. Что НЕ установлено, и чем это грозит генератору

1. **Бит1 (2) у flag LwPolyline.** Встречается у открытых (2, 6) и замкнутых (3). С обходом,
   технологическим слоем, LeadParam, видом блока и порядком в цепочке совмещённого реза не связан
   (проверено в geo_explore5/6/13). Риск низкий: писать 1 (замкнутая) или 0 (открытая). Оба значения
   массово встречаются в настоящих файлах, всего 694.
2. **Бит2 (4)** — только у кусков совмещённого реза, которые сгенерировал CypCut. Генератору его не ставить.
3. **Постоянные нули** (u32 в вершине, u32 после вершин, u32 и 8 байт у Circle, зарезервированные u32 заголовков):
   смысл неизвестен. Ненулевых значений нет ни в одном образце, поэтому писать 0.
4. **start_param ≠ 0 без LeadParam** (9 случаев) — почему так, не выяснено. Генератор пишет 0, старт в вершине 0.
5. **Нецелый start_param и вершин больше 20** в образцах не встречались. Формат это допускает (f64, u32 n),
   но поведение CypCut на таких данных не проверено.
6. **Типы Arc, Text, Spline, Ellipse, Point** в образцах не встречались, формат их записи неизвестен. Генерировать
   только Line / LwPolyline (дуги через bulge) / Circle.
7. **Проверяет ли CypCut MD5 и порядок объектов**, неизвестно. Оба воспроизводятся точно, так что риска нет, если повторять правило.
8. **Файл без объектов** (только заголовок) не встречался.
9. При любой правке геометрии меняются адреса всех следующих объектов. **GeoAddr в Shapes2D/content.xml
   нужно брать из `build_data_bin`**. Это работа той части, которая пишет Shapes2D.

## 6. Поправки к README старого расшифровщика (раздел 5)

- Подтверждено: Line (метка + 2 double), Circle (центр, r, 4 служебных байта = 0, угол), вершина LwPolyline
  по 32 байта (служебные 4 байта = 0), бит 0 флага = замкнутость.
- Уточнено: перед флагом LwPolyline лежит **f64 start_param**. У 27 замкнутых контуров рез начинается
  в вершине start_param, а не в вершине 0. Старый отчёт берёт `pts[0]` как точку старта, поэтому оценка
  холостого хода у этих контуров слегка неточна.
- Длина объекта (u32 по +8) **не включает** дополнение до 8. Следующий объект начинается с `align8(GeoAddr + длина)`.
