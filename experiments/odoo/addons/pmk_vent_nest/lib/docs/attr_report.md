# Shapes2D/data.bin: записи атрибутов контуров (тема `attr`)

Образцы: 5 программ CypCut 6.3.907 (zonty, m14, m30, m3_grpsh, m8_plates). Всего 3978 записей.
Все утверждения ниже проверены кодом на всех 5 файлах:
- `attr_codec.py` — кодек;
- `attr_analysis.py` — статистика и связи, вывод лежит в `attr_analysis_out.txt`;
- `attr_plateorder.py` — порядок записей.

## 0. Итог проверки (побайтово, полный файл)

| образец | байт | записей | generic parse→serialize | typed decode→encode | с нуля `encode_attr`+`build_data_bin` | DataAddr совпали | MD5 = `<MD5>` в content.xml |
|---|---|---|---|---|---|---|---|
| zonty | 331168 | 1303 | 0 разных байт | 0 разных записей | 0 разных байт | да | да |
| m14 | 489456 | 1412 | 0 | 0 | 0 | да | да |

| m3_grpsh | 21120 | 65 | 0 | 0 | 0 | да | да |

В строгом режиме сериализатор сам пересчитывает длины, выравнивание, адреса и размер в заголовке.
Каждое значение он сверяет с прочитанным, поэтому совпадение байт заодно подтверждает правила длины и
размещения. Синтетический тест проверяет вложенную подзапись, неизвестное имя и нечётные зазоры: такая
запись проходит туда и обратно, а запись с испорченной длиной отвергается.

## 1. Устройство файла

- **Заголовок 0x1000 байт:** `"BCMP"`, u32 = полный размер файла, u32 = 1, далее нули до 0x1000.
  Хвоста после последней записи нет.
- **Записи (объекты)** лежат подряд с 0x1000. Каждая выровнена на 8: после маркера `d0d0d0d0` идут 4
  нулевых байта, потому что длина любой записи ≡ 4 (mod 8).
- **Правило DataAddr:** `addr[0] = 4096`, `addr[i+1] = addr[i] + roundup8(L[i])`.
  - Порядок записей в data.bin совпадает с порядком элементов в `Shapes2D/content.xml`.
  - Порядок в content.xml: сначала контуры из `Blocks` (блоки по порядку, внутри блока по порядку
    `<Shape>`), затем полилинии листов: сначала `Nest2D/Plates`, потом листы `Results/1..N`.
  - Правило выполнено 5/5. Хэндлы при этом не отсортированы.
- **`<MD5>` в Shapes2D/content.xml** = MD5(data.bin) в верхнем регистре (5/5). То же правило выполнено
  для Geometry2D (5/5).
- **Поток упакован без выравнивания полей:** u32 и double могут стоять по адресу ≡ 4 (mod 8), например
  LeadParam всегда начинается с addr%8 = 4.
- **Строка с меткой:** u16 0x0053 `'S'`, u16 n, n байт ASCII, затем нули, чтобы 4+n стало кратно 8
  (считается от начала строки, а не от начала файла).
- **Подзапись:** `c1c1c1c1`, u32 ver, u32 длина (от c1 до c0 включительно), u32 0, строка-имя, поля,
  `c0c0c0c0`.
- **Объект:** `d1d1d1d1`, u32 0, u32 длина (от d1 до d0 включительно), u32 0, строка-класс
  `"TGks"+класс`, тело, `d0d0d0d0`.

### Раскладка записи

Смещения указаны от начала объекта, для LwPolyline. У Circle и Line строка класса занимает 16 байт, поэтому
все смещения после неё меньше на 8. `n` — число LeadParam (0 или 1).

| смещ. | размер | поле |
|---|---|---|
| 0 | 16 | `d1d1d1d1`, 0, L, 0 |
| 16 | 24 | Str `TGksLwPolyline` (у Circle/Line 16 байт: `TGksCircle`, `TGksLine`) |
| 40 | 40 | подзапись **Object** v1 L=40: Str `Object` + **u32 handle** |
| 80 | 88 | подзапись **Shape** v6 L=88: Str `Shape` + 13×u32: `[layer,0,0,0,0, coedge,0,0, flag64,0,0,0,0]` |
| 168 | 4 | u32 **n_lead** (0/1) |
| 172 | 96·n | подзапись **LeadParam** v1 L=96: Str `LeadParam` + 5×u32 `[0,kind,0,0,0]` + 5×f64 `[d52,d60,d68,d76,d84]` |
| 172+96n | 4 | u32 **tail_count** (всегда 0: длина ещё одного списка, формат элемента неизвестен) |
| 176+96n | 72 | подзапись **Curve** v2 L=72: Str `Curve` + 9×u32: `[outer,0,1,0,0,0,0,0,6]` |
| 248+96n | 4 | `d0d0d0d0` |
| 252+96n | 4 | нули до кратности 8 |

**Длина записи:** `L = 16 + strsize(класс) + 40 + 88 + 4 + 96·n + 4 + 72 + 4`.

| класс | L без LeadParam | L с LeadParam | занимает места (выделено) |
|---|---|---|---|
| LwPolyline | 252 | 348 | 256 / 352 |
| Circle, Line | 244 | 340 | 248 / 344 |

## 3. Поля: значения, смысл, связи

| поле | значения (3978 записей) | смысл (подтверждено / гипотеза) |
|---|---|---|
| Object.handle | = XML `Handle` в 3978/3978 | **хэндл контура**. Других ссылок на хэндлы в записи нет: ни на исходный контур детали, ни на блок, ни на деталь |
| Shape+32 `layer` | 1: 2979, 2: 979, 0: 20 | **технологический слой**. 0 — ровно все 20 полилиний листа (Plates и Results), 1 — рез, 2 — гравировка (все Line в m30 и часть LwPolyline). Не зависит от XML `LayerName` («0», «Системный слой» и отсутствующий встречаются и с 1, и с 2) |
| Shape+52 `coedge` | 0: 3718, 1: 260 | **= (LwPolyline ∧ незамкнутая ∧ слой 1) — 3978/3978**. Это отрезки совмещённого реза CoedgePart: 117 в блоках раскладок групп, 143 в устаревших блоках групп (на них не ссылаются ни Parts, ни Results) |
| Shape+64 `flag64` | 0: 3964, 1: 14 | **НЕИЗВЕСТНО**. 1 только у 14 контуров гравировки (слой 2) в двух блоках деталей m30: 12 Line блока «Деталь1» и 2 LwPolyline блока {F48D…}. У третьей детали m30 и у всех копий в раскладках — 0 |
| n_lead | 0: 2552, 1: 1426 | есть ли LeadParam |
| LeadParam | 2 варианта, см. ниже | подвод или перенесённая точка старта |
| tail_count | 0: 3978 | длина второго списка; всегда пуст |
| Curve+32 `outer` | 1: 1054, 0: 2924 | **внешний контур детали**. Совпадает с выведенным правилом в 3978/3978, правило — сразу под таблицей |
| Shape: остальные 10 слов | все 0 | константы |
| Curve+36..+60 | `0,1,0,0,0,0,0` | константы (+40 = 1) |
| Curve+64 | 6 во всех записях | константа. Гипотеза: это `LeadInOptimizeFlag="6"` (атрибут с тем же значением стоит у полилинии листа в Plates во всех 5 файлах) |
| версии подзаписей | Object 1, Shape 6, Curve 2, LeadParam 1 | одинаковы в 6.3.907.8 и в более новой сборке |
| служебные u32 заголовков (+4, +12 объекта; +12 подзаписи) | все 0 | константы |

**Правило для `outer` (Curve+32), выполнено 3978/3978.** Флаг равен 1, если выполнено одно из условий:
- у блока есть `OutlineID`, и хэндл контура совпадает с ним;
- контур — незамкнутый отрезок совмещённого реза (coedge);
- в блоке группы или раскладки контур скопирован из детали, и у исходного контура детали флаг равен 1;
- замкнутый контур слоя 1 в блоке группы, у которого нет пары среди деталей: это новый слитый внешний
  контур, CypCut создаёт их при совмещённом резе (только в блоках раскладок: 7 в zonty и 7 в m30, ещё
  есть в устаревших блоках групп);
- у блока детали без OutlineID (m30 «Деталь1») — самый внешний замкнутый контур.

Во всех остальных случаях флаг равен 0: отверстия, гравировка и лист.

**Чего в записи нет.** Нет направления реза: `outer` встречается и при обходе по часовой стрелке, и
против. Нет номера по порядку, габаритов, привязки к блоку или детали. Нет точки старта, кроме LeadParam:
для окружности угол старта хранится в Geometry2D.

**Варианты LeadParam (больше ни одного не встретилось):**

| где | слова w32..w48 | d52 | d60 | d68 | d76 | d84 | сколько |
|---|---|---|---|---|---|---|---|
| m14, Circle в раскладке | 0,1,0,0,0 | 0 | π/2 | 5.0 | 1.0 | 0.5 | 1408 |
| LwPolyline в блоках групп (m30 11, m3 4, m8 3) | 0,0,0,0,0 | 2, 3, 4, 5 | 0 | 0 | 0 | 0 | 18 |

- **Полилинии.** Гипотеза: d52 — параметр кривой точки старта, то есть номер вершины. В m3 и m8
  вершина [d52] = (0.2; 0.2), а это вершина 0 исходной детали (0; 0) со сдвигом раскладки. Все 18
  случаев — пересобранные (слитые) контуры групп CoedgePart, у которых начало полилинии не совпадает со
  стартом.
- **Окружности.** Гипотеза: w36 = 1 — тип подвода, π/2 — угол, 5 — длина, 1.0 и 0.5 — прочие
  параметры. В m14 поле стоит у всех 1408 окружностей раскладки, у 2 окружностей детали его нет.
  Угол старта в Geometry2D у всех 1410 окружностей m14 одинаковый: π/4.

## 3b. Контур детали против его копии в раскладке

Пары сопоставлены по классу и размеру (радиус; либо число вершин, площадь и периметр); собственный
хэндл в сравнении обнулён. Всего 2583 пары.

| результат | пар | разница |
|---|---|---|
| идентичны побайтно | 913 | нет |
| m14 | 1408 | в раскладке **добавлен LeadParam** (длина 244 → 340) |
| m30 | 260 | различается только байт 136 или 144, то есть **Shape+64 flag64**: в детали 1, в раскладке 0 |
| m3 и m8 | по 1 | в раскладке добавлен LeadParam |

Пример идентичной пары: zonty, контур 1505 в блоке детали {BCEDEC63…} и контур 2465 в блоке раскладки
{93D721AA…}. Они различаются только словом хэндла (смещение 72).

Вывод: копия в раскладке = запись детали с новым хэндлом. layer, coedge и outer наследуются, flag64
сбрасывается в 0, LeadParam CypCut может добавить при раскладке.

## 4. Запись с нуля: какие входные данные нужны

`encode_attr(handle, cls, layer=1, outer=False, coedge=False, flag64=0, lead=None)` возвращает байты
записи, `build_data_bin([...])` возвращает `(data.bin, DataAddr[])`.

Сравнение с настоящими записями, по числу совпавших записей:

| набор входов | zonty | m14 | m30 | m3_grpsh | m8_plates |
|---|---|---|---|---|---|
| A: все переменные поля | 1303/1303 | 1412/1412 | 1178/1178 | 65/65 | 20/20 |
| B: handle, cls, layer, outer; coedge выведен; flag64=0; без LeadParam | **1303/1303** | 4/1412 | 1153/1178 | 61/65 | 17/20 |
| C: как B, но outer тоже выведен из XML и геометрии | 1303/1303 | 4/1412 | 1153/1178 | 61/65 | 17/20 |
| D: C + flag64 + LeadParam из двух конструкторов (`lead_start_only(k)`, `lead_circle_m14()`) | 1303/1303 | 1412/1412 | 1178/1178 | 65/65 | 20/20 |

Расхождения в B и C объясняются только тем, что этих полей нет на входе:

| образец | причина | записей |
|---|---|---|
| m14 | LeadParam у окружностей | 1408 |
| m30 | LeadParam у полилиний | 11 |
| m30 | flag64 | 14 |
| m3_grpsh | LeadParam | 4 |
| m8_plates | LeadParam | 3 |

Других расхождений нет. Байтовое число в выводе велико, потому что одна пропущенная LeadParam сдвигает
весь хвост файла; показательно число записей.

**Минимальный набор для генератора:**
- **`handle`** — тот же, что в XML;
- **класс**;
- **технологический слой**: 1 рез, 2 гравировка, 0 для полилинии листа;
- **`outer`**: 1 для внешнего контура детали (тот же хэндл, что `OutlineID` блока) и для отрезков
  совмещённого реза.

`coedge` выводится как «незамкнутая LwPolyline на слое 1». Всё остальное — константы.

На zonty, самом близком к нашей задаче образце, этих входов достаточно: 1303/1303, файл совпадает
побайтно. Рекомендация: LeadParam не писать (n_lead = 0), flag64 = 0. Ровно так CypCut сам записал все
контуры zonty, а flag64 = 0 он пишет во все копии в раскладках.

## 5. Неизвестное

1. **Shape+64 flag64.** Смысл неизвестен: 14 случаев, только гравировка в блоках деталей m30, в копиях
   0. Риск при записи 0 низкий: так выглядят все раскладки.
2. **Постоянные слова** (10 слов Shape, Curve+40 = 1, Curve+64 = 6, нули в заголовках). Смысл
   неизвестен, во всех 3978 записях и в обеих версиях CypCut значения одинаковые. Риск: через них нельзя
   задать настройки, которые, возможно, там живут (сторона компенсации, микроперемычки, охлаждение).
   Пишем константы, то есть состояние «по умолчанию».
3. **Список после LeadParam (tail_count)** всегда пуст, формат элемента неизвестен. Пишем 0, риск низкий.
4. **Смысл полей LeadParam** — гипотезы, видно всего 2 варианта. Риск средний, если захотим сами задавать
   подводы; низкий, если не писать LeadParam (как в zonty).
5. **Слои > 2** не встречались; поле u32, скорее всего это номер 1..16.
6. **Классы кроме LwPolyline, Circle и Line** (Arc, Text, Spline, Ellipse) не встречались. Раскладка
   записи для них, вероятно, та же с другой строкой класса, но это не проверено.
7. **Проверяет ли CypCut `<MD5>`** при открытии, неизвестно. Генератор всё равно его пишет: правило
   подтверждено.
8. **Строки не-ASCII** в метках не встречались (здесь только имена классов и подзаписей).
