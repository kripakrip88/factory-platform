# pmk_tech — технический расчёт и заявка на металл

Разбор удобства, шаг З-4 (08.10.2026), карточка 4 проекта «Заказ от заявки
до цеха». Решения Антона 07–08.10.2026: инженер (Игорь Бутов) может
переделать состав и заменить материалы, а не только число листов; работает в
«Техническом расчёте» — копии расчёта менеджера у той же сделки; расчёт, по
которому ушли КП и счёт, остаётся нетронутым. Действие — «Заявка на металл»,
закупщик (Владимир Голубенко) видит список «Заявки на металл». «Поюзаем,
потом правки».

## Путь

| Где | Кнопка | Что происходит |
|---|---|---|
| Счёт покупателю (в работе) или строка «Заказов в работе» | **Технический расчёт** | Копия расчёта, по которому выставлен счёт: изделия, состав, листовые детали, раскладка, отпечаток раскладки. Своя нумерация СМ-, та же сделка, клиент, организация, ссылка на счёт. Цены закупки — на сегодня. Повтор открывает тот же (один на счёт). Счёт без расчёта — пустой технический. |
| Технический расчёт | правка как обычно | Тот же экран расчёта: состав, материалы, «Разложить листы». Под заголовком «Технический расчёт к СЧ-… · по КП СМ-…», карточка «Металл в заявку, т: по КП → сейчас» на месте карточки «Металл к закупке» (одной мерой: целые листы раскладки с обеих сторон). «КП (PDF)» и «Отправить КП» спрятаны. Счёт выставили заново после копии (новая редакция, другой расчёт) — плашка «сверьте состав». «Дублировать» — снова технический (без счёта), главным расчётом сделки не становится. |
| Технический расчёт или строка планировщика | **Заявка на металл** | Черновики заказов поставщику — по одному на назначенного поставщика позиции. Строка планировщика ЭТОГО счёта (не другого счёта той же сделки) — «Ждём металл» из «Очереди» / «Разработки чертежей», «Металл: Ждём»; этап без кода («Разобрать: прошлые месяцы») не трогается. |
| Закупки → **Заявки на металл** | — | Список заявок: поставщик, сделка, клиент, счёт, технический расчёт, сумма, ожидаемое прибытие, состояние. Отправить поставщику, подтвердить — штатными кнопками. |

## Что идёт в заявку

- **Прокат** — метры: длина × кол-во на изделие × изделий / использование
  (как «Металл к закупке»). В описании — «≈ N хлыстов по L м», если длина
  хлыста есть в прайсе.
- **Лист** — числом листов раскладки (по товару и габариту). Деталь без
  раскладки — по весу, до целого листа, и плашкой на техническом расчёте и
  в его ленте (в описание строки заказа не пишется: его видит поставщик).
  Масса листа — масса м² × площадь габарита. Лист не 1500×6000 — цена
  ручная: строка прайса заведена за 1500×6000, ядро после правки
  количества поставило бы её. Без цены такой лист — мина шага 57.
- **Метизы** — штуками, **покрытие** — килограммами; услуга («не материал»)
  в заявку не идёт.
- **Цена** — по прайсу назначенного поставщика (тот, у кого её взял расчёт):
  ₽/т × вес → цена за единицу заказа. Без цены — сигнал «в городе нет»:
  позиция идёт в черновик на служебного «Поставщик не выбран» с ценой 0,
  соседний размер не подставляется.

## Повторная заявка

Ключ позиции хранится в строке заказа (`pmk_request_key`). Черновик —
обновляется (количество, цена, описание; пропавшие позиции удаляются,
опустевший черновик отменяется). **Правки закупщика целы:** строка помнит,
что записала заявка (`pmk_request_qty` / `_price` / `_name`); поле, которое
закупщик поменял (округлил прокат до хлыста, вписал договорную цену, своё
описание), повтор не перезаписывает, такую строку не удаляет и к другому
поставщику не переносит; расхождение количества — плашкой «Расходится с
заявкой». Плашка «Состав изменился после заявки» — от изменения у
инженера, а не от правки закупщика (и только «Закупкам»: кнопка у них). Отправленная поставщику и подтверждённая
заявка не меняются — на техническом расчёте плашка «В заявке P00014 (заказ
подтверждён): Лист 2 мм — 11 листов, у инженера 12 листов». Позиция, у
которой появилась цена, переезжает из «Поставщик не выбран» к поставщику.

## Что знает заявка

`pmk_tech_spec_id` (технический расчёт), `pmk_sale_order_id` (счёт),
`pmk_deal_id` (сделка), `pmk_task_id` (строка планировщика — для карточки 5
«Материал пришёл»: поставить «Металл: получен»), `pmk_client_id`.

## Ничего не блокирует

Нет раскладки — листы по весу; нет цены — «Поставщик не выбран»; нет строки
планировщика — заявка всё равно собирается. Писем нет: черновики отправляет
закупщик сам.

## Установка

```
INSTALL="pmk_tech" sh deploy.sh
```

Тем же прогоном `-u pmk_deal` (главный расчёт сделки — без технических) и
`-u pmk_flow` («Связи»). Список изменённого — `docs/disabled-features.md`,
шаг З-4. Тесты — `tests/` (одноразовая база, см. `tests/__init__.py`).
