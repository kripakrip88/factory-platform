# sheet_nest — раскрой листового металла → программа CypCut (.lxds)

Статус: шаг 1 (12.10.2026, одобрено Антоном «поехали»). Отдельный модуль (принцип изоляции CLAUDE.md):
своя папка `experiments/sheet_nest/`, ветка `feature/sheet-nest`; в ERP — после проверки на станке.

Зачем: CypCut даёт раскладку не больше 20 листов; заказы больше — раскладывает наш инструмент. Образец —
решётки 1,5 цинк 12.10 (`~/Downloads/vent_nesting/reshetki/`, разовые скрипты): 77 листов (доказанный минимум),
холостой ход 506 м против 2241 м у порядка из блоков инженера.

## Поток

    вход (DXF из КОМПАСа/AutoCAD | программа CypCut с листами или без) → детали (Part)
    → раскрой (портфель: прямоугольный упаковщик pack_rect | растровый v1 пакета) → листы (Sheet)
    → порядок резки (route: змейка по рядам | оптимизатор) → .lxds (write_lxds, эталонный сборщик пакета)
    → проверки (verify) + картинка (render) + JSON

Общий код берётся из пакета раскроя зонтов `experiments/odoo/addons/pmk_vent_nest/lib/vent_nesting`
(cypcut/spec_rebuild — сборщик .lxds байт в байт с заводскими; lxds_reader — расшифровщик; nest.py — растровый v1)
через `sheet_nest/libpath.py`. Пакет НЕ меняется из этого модуля (кроме отдельных веток пакета по договорённости).
Только стандартная библиотека + numpy + Pillow (как в контейнере Odoo; scipy/ezdxf нет).

## Модель (общая для всех модулей)

Фигура (shape) — словарь как в `spec_rebuild` (тот же формат пишет сборщик):

    общее:  handle=None, kind, layer (1 — рез, 2 — гравировка), layer_name="0", coedge=0, flag64=0, outer=0|1, lead=None
    Line:        p1=(x, y), p2=(x, y)
    Circle:      c=(x, y), r, a0 (угол точки врезки, рад; по умолчанию π/4)
    LwPolyline:  verts=[(x, y, bulge), …], flag (бит 1 — замкнута), sp=0.0
                 bulge = tan(угол дуги/4), + — дуга против часовой (как DXF LWPOLYLINE)

Деталь (Part) — словарь:

    name: str            имя детали (в программе CypCut; без &<>"')
    qty: int             количество
    shapes: [shape]      в координатах детали; ВНЕШНИЙ КОНТУР ПОСЛЕДНИМ: LwPolyline замкнута, layer 1, outer=1
                         (окружность-деталь — Circle с outer=1); внутри: отверстия (замкнутые, слой 1),
                         открытые резы (слой 1, незамкнутые — прорези), гравировка (слой 2, любые)
    src: str             откуда (файл)
    warnings: [str]      что пропущено/приближено при чтении (текст, размеры, сплайн → дуги и т.п.)

Лист (результат раскроя): `{"W": 1250.0, "L": 2500.0, "amount": n, "placed": [{"part": i, "rot": 0|90|180|270,
"dx": .., "dy": ..}]}` — поворот против часовой вокруг начала координат детали, затем сдвиг (как
`spec_rebuild.transform_shape(s, rot, (dx, dy))`). Лист в координатах CypCut: X 0…W, Y 0…L.

### read_dxf.py — договорённость о гравировке
`parts_from_dxf(data: bytes, filename: str, qty=None, engrave_layers=None) -> [Part]`, ошибка — `DxfError` (по-русски).
- Слой гравировки — по имени слоя (код 8), без учёта регистра: «ГРАВИРОВКА», «Гравировка», «GRAV», «ENGRAVE»,
  «MARK», «МАРКИРОВКА», а также имя, содержащее «грав»/«engrav». Остальные слои — рез. Список переопределяется.
- Сущности: LINE, ARC, CIRCLE, LWPOLYLINE (bulge), POLYLINE+VERTEX (R12, bulge), SPLINE (приближение дугами/
  отрезками, отклонение ≤ 0,01 мм; предупреждение), ELLIPSE (так же), INSERT (блоки с масштабом/поворотом/сдвигом,
  вложенные), POINT — пропуск. TEXT/MTEXT/DIMENSION/HATCH/LEADER — не режутся: пропуск с предупреждением.
- Кодировка: AC1018 и старше — $DWGCODEPAGE (ANSI_1251 → cp1251), AC1021+ — UTF-8; escape \U+XXXX в строках.
- Единицы: $INSUNITS 4 (мм) / 0 (нет — считать мм, предупреждение) / 1 (дюйм ×25,4) / 5 (см ×10) / 6 (м ×1000).
- Сцепка рёбер в контуры с допуском 0,01 мм (как contours._node_ids пакета); замкнутая цепочка → LwPolyline flag=1;
  незамкнутая → LwPolyline flag=0 (на слое реза — открытый рез, на слое гравировки — гравировка).
- Несколько деталей в одном файле: внешний контур = замкнутый контур слоя реза, не лежащий внутри другого; всё,
  что внутри него, — его. Фигуры вне всех внешних — ошибка. Разрыв внешнего контура (не замкнулся) — ошибка
  с координатами разрыва.
- Внешний контур — против часовой, отверстия — по часовой (нормализовать направление).
- Количество: аргумент qty; иначе из имени файла (`…_12шт.dxf`, `… x12.dxf`, `…(12).dxf`); иначе 1 + предупреждение.

### pack_rect.py — прямоугольный раскрой
`pack_rect(items, W, L, gap, edge, rotations=(0, 90), node_limit=…) -> dict`
- items: `[{"id", "w", "h", "qty"}]` — габарит детали при повороте 0 (w — вдоль X листа, h — вдоль Y).
- Результат: `{"sheets": [[{"id", "rot", "x", "y", "w", "h"}]], "lower_bound": int, "optimal": bool, "method": str}`;
  x, y — левый нижний угол повёрнутого габарита; всё в [edge, W−edge]×[edge, L−edge]; между габаритами ≥ gap.
- Двухэтапный гильотинный: полосы вдоль Y (ширина полосы — по X), в полосе детали вдоль Y; полосы — рядом по X.
  И обратная ориентация (полосы вдоль X); лучшее.
- Точный случай: если в лист влезает только одна полоса (любые две детали поперёк не встают) — задача = 1D-упаковка
  вдоль Y; решать ТОЧНО (bin completion / ветви и границы с нижней границей L2 Мартелло–Тота, предел узлов) —
  решётки обязаны дать 77 листов при W=1250, L=2500, gap=edge=2.
- Нижняя граница: max(по площади габаритов с зазором, L2 для 1D-случая).

### Порядок резки (route.py)
- Внутри детали: элементы (отверстия, открытые резы, гравировка) путём от головки к точке врезки внешнего контура;
  внешний — последним. Открытые элементы можно развернуть.
- Ряды параллельных открытых резов (жалюзи) — змейка по рядам с рисками у концов (как у решёток); иначе —
  оптимизатор (ближайший сосед + 2-opt/перенос с разворотом). Берётся короче из вариантов БЕЗ переходов над
  вырезанным (язычок открытого реза, отверстие).
- Точка врезки внешнего контура: выпуклая вершина между прямыми участками, свободно ≥ 10 мм по наружной нормали
  к первому участку (край листа, соседи). Динамика по деталям листа.
- Стратегии (минимум холостого / безопасный / безопасный с концом у нуля) и счёт опасных переходов — раздел
  «Стратегии порядка резки» ниже.

### write_lxds.py
- Сборка через `spec_rebuild.compile_lxds` + `fresh_identity`; детали — блоки деталей как есть; раскладки — вставки
  с фигурами в порядке резки. Признак общего реза (coedge) — ТОЛЬКО у настоящих цепочек общего реза (шаг 2);
  открытые прорези — coedge=0 (так у CypCut инженера; правило пакета «открытая полилиния слоя 1 = общий рез» неверно).
- Технология (Technical/content.xml) — из входной программы CypCut, иначе шаблон пакета.
- Время сохранения — заводское UTC+10 (как в пакете).
- Один файл на материал на нужное число листов (CypCut читает файлы любой длины; ограничение 20 листов — только
  на его собственный раскрой).

### Стратегии порядка резки и опасные переходы (route.STRATEGIES, risk.py) — 13.10.2026, правки по ревизии 14.10
Решения Антона: стратегий несколько, инженер выбирает по опыту, программа показывает сводку по каждой; общий рез —
кнопка, одна из стратегий, сам не выключается (экономит много машинного времени); не уходить над только что
вырезанной деталью — правило: деталь меньше 100 мм по одной из двух сторон (встаёт между ламелями) или без
микроперемычек; «лист проваливается между ламелями и при 0,5, и при 30 мм» — у правила мелких деталей нет предела
по толщине. Время по станкам — потом: станков два, режимы (.fsm) Антон запросит и пришлёт с каждого отдельно —
заготовка `machine.py` (профиль на станок, `--machine` повторяется — строка времени на каждый станок), без выдумки.

Классы перехода (risk.py; переход — от конца реза к следующей врезке; «над» — ≥ 0,5 мм пути глубже 1 мм в детали,
глубже 0,5 мм в отверстии или язычке; считается точно — участки внутри минус «капсулы» рёбер, окружность по хорде):
- язычки — над вырезанным открытым резом слоя реза, замкнутым по хорде (площадь ≥ 1 мм²; дуговая прорезь из двух
  вершин — тоже), у не освобождённой детали;
- мелкие / детали — над освобождённой деталью: «мелкая» — меньше `--small` (100) по меньшей стороне габарита,
  толщина не важна; деталь освобождена после последнего куска своего контура (в группе — после своей цепочки);
- отверстия ≥ 10 / < 10 — над вырезанным замкнутым внутренним контуром: размер — диаметр вписанной окружности
  (у паза — ширина; 4·S/P у паза вдвое больше ширины — ошибка прототипа 13.10). Классу нужен только ответ «≥ 10 или
  нет»: `risk.hole_big` — поиск по ячейкам до ответа (точка глубже 4,97 мм — да; ни одна ячейка не может быть глубже
  4,98 — нет) с кэшем по форме контура (поворот начала и место детали — та же форма). Полный поиск вписанной
  окружности (`inscribed_d`) у длинного паза шёл до 0,01 мм по всей длине — секунды на паз (ревизия 14.10: маршрут
  «short» в 10–50 раз дольше на деталях с пазами), теперь — доли миллисекунды;
- впритирку — не над деталью, но ближе 5 мм к освобождённой (без первых и последних 10 мм — уход от только что
  вырезанного контура и подход к врезке у соседки — не в счёт);
- короткие (< 10 мм: CypCut может идти без подъёма), с перемычками (над деталью с микроперемычками) — в отчёт;
- возврат в ноль после листа (настройка станка, в .lxds его нет): длина, метры над деталями, язычков под ним — в итогах
  и у каждой раскладки (`layouts[].risk.ret`).
Детали с микроперемычками (`--microjoints`) держатся в листе: правила освобождённых к ним не применяются, их отверстия
и язычки опасны и после контура. Счёт не знает устройства маршрута — на входе фигуры в порядке резки с номером
размещения; сверен с независимым пересчётом по готовой программе (`tests/recount_lxds.py`: numpy-точки через 0,1 мм,
освобождение — по покрытию контура, вписанная окружность — перебором; возврат в ноль — тоже) — совпадает на всех
образцах и стратегиях.

Ключ безопасных стратегий (лист, по порядку; `risk.safe_key`) и почему так:
1. язычки — отогнутый язычок бьётся на полном ходу; строго выше отверстий (прототип менял 1 язычок на 47 отверстий;
   ревизия 14.10 нашла то же в выборе начала отверстия — исправлено, см. ниже);
2. освобождённые мелкие — встают между ламелями при любой толщине;
3. прочие освобождённые без перемычек — могут встать на ребро;
4. отверстия ≥ 10 мм — сопло проваливается; НИЖЕ деталей: иначе короткий выход из отверстия менялся на длинный
   переход над освобождённой соседкой (прототип, 11 из 40 синтетических раскладок);
5. холостой + NEAR_COST (500 мм) за каждый переход впритирку (прототип 13.10: строго выше холостого — решётки +54 м;
   без учёта — впритирку на m30 в 2,4 раза больше).
`safe0` — тот же ключ, но возврат в ноль — ещё один переход: в ступенях опасных и в холостом (`key0`). Переход —
как любой другой: над сколькими деталями он прошёл, в ключе не важно (m30, раскладка №1: возврат над плитами вместо
перехода над плитой в программе — та же ступень, путь короче). Если Антон решит иначе — возврат отдельной ступенью
или по числу деталей под ним — это одна строка в `risk.measure` (key0).

Стратегии — словарь переключателей (новая — строка в `STRATEGIES`):
- `short` — ключ «как было» (штрафы 2000/500 мм) + начала отверстий, одинаково свободные углы у деталей без места
  под подвод, «взгляд вперёд» в группах, и (с 14.10, `orders`) порядок деталей ещё змейкой по рядам и замкнутым обходом:
  та же динамика «как было», берётся порядок с меньшей её ценой (ближайший сосед — первым, другой — только если дешевле).
  Ревизия 14.10: «Минимум холостого» проигрывал «Безопасному» по холостому (250 кронштейнов: 22,0 м против 20,4 м —
  у безопасного были другие порядки). Теперь 20,2 м; m14 — 75,2 м (было 81,4), m30 — 83,4 м (было 90,6), зонты —
  110,4 м (было 113,0);
- `safe` и `safe0` выбирают из ОДНИХ кандидатов (`_safe_pool`, общий рез — `_coedge_pool`), каждая — лучший по своему
  ключу. Поэтому на любой раскладке safe не хуже safe0 по ключу без возврата, safe0 не хуже safe по ключу с возвратом,
  и обе не хуже `short` (его маршрут — тоже кандидат). Проверяется тестом на каждой раскладке образцов и 200
  синтетических. Ревизия 14.10: у safe0 были только ближайший сосед и замкнутый обход — на рядах мелких деталей он
  оставлял 96 переходов над ними там, где safe — 0, и писал «без них не обойти»; а safe на m30 проигрывал замкнутому
  обходу safe0 по своему же ключу (5 переходов над плитами против 2).

Кандидаты (`_safe_pool`; выбор между ними — всегда по счёту `risk.measure` готового маршрута, тем же, что в отчёте):
- динамика по трём порядкам деталей: ближайший сосед + 2-opt по центрам, замкнутый обход от нуля и обратно (в обе
  стороны). У каждого прогона динамики — два конца: лучший без возврата и лучший с возвратом (возврат зависит только от
  точки врезки последней детали — от последнего состояния);
- маршрут `short` (те же переключатели);
- остались опасные (у лучшего без возврата или у лучшего с возвратом) — порядки «ближайший без опасных» (из 12
  ближайших — та, переход к которой не над освобождёнными), «мелкие последними», змейкой по колонкам и по рядам — пока
  опасные не уйдут;
- правка порядка около опасных переходов (`_repair`): по ступеням ключа, прицельно — деталь, к которой шёл переход,
  вырезать раньше пересечённой; пересечённую — после неё или последней (её единственный угол врезки смотрит прочь от
  остальных — синтетика 14.10, сид 35); развернуть участок между ними; затем окно ±3 места. Вариант принят, если
  ступени опасных строго лучше. Динамика продолжается с места первого изменения от сохранённых состояний (трасса
  прогона), поэтому вариант стоит n − a шагов, а не n. Бюджет — REPAIR_WORK (4) проходов на лист, у опасных в программе
  не меньше 80 шагов; прежде правка шла только для мелких деталей (m30 оставлял 5 переходов над плитами, которые
  обходятся) и стоила до 80 полных прогонов (ревизия: 8–28× времени маршрута на случайных листах);
- лист до 6 деталей с опасными в программе — все порядки деталей той же динамикой (перестановки по порядку, общее
  начало — от его состояний: 1956 шагов на 720 порядков). Синтетика (600 плотных раскладок): где перебор обходится без
  переходов над мелкими, safe обходится во всех (прежде 79 из 80; тест требовал ≥ 95 %, теперь — все).
Работа безопасной стратегии на лист ограничена: 3 прогона + `short` + до 4 порядков + правка ≤ max(4n, 80) шагов на
ключ (тест считает шаги на листе с неустранимыми переходами).

Устройство динамики безопасных: состояние — точка врезки предыдущей детали, ключ — сумма векторов классов
(лексикографический порядок совместим со сложением — динамика точная по точкам врезки). Пути по детали: змейка, путь
оптимизатора (точный от головки — для 3 лучших состояний, иначе со свободным началом), начала отверстий; остался
опасный заход — другой первый элемент (разворот начала пути: холостой — суммами, полностью считаются 3 лучших).
Кэши на все прогоны листа (вырезанное к детали зависит от порядка, поэтому ключ — «что вырезано рядом»): путь внутри
детали — (путь, вырезанное в габарите её внутренних фигур ± 5 мм); лучший путь по детали от головки — (головка, угол,
вырезанное в габарите головка + деталь ± 5 мм). Те же числа, что без кэша: все переходы и «впритирку» — в этом габарите.

Начало отверстия (`choose_starts`): окружность — 16 углов, полилиния — вершины без поворота внутрь острее 90° (не
больше 16 — через равные промежутки: окружность ломаной из CAD давала 33 варианта), исходное — среди вариантов. Ключ
выбора: `safe` — (переходов над язычками своей детали, над её отверстиями ≥ 10 мм — и выход над самим отверстием,
вход + выход, выход над самим < 10 мм): язычки строго выше отверстий (ревизия 14.10: одна ступень на оба — safe0 шёл над
язычком ради выхода не над отверстием); `short` — (над язычками, вход + выход, выход над собой). Варианты — по
возрастанию пути, ступени считаются, только пока вариант ещё может быть лучше; препятствия — из сетки вырезанного
своей детали, только у перехода; выбор у отверстия запоминается по (отверстие, вход, выход, что вырезано до него) —
прежде пересчитывался для каждого состояния динамики и варианта змейки (ревизия: жалюзи с 4 отверстиями — 5–9× дольше
50ed4af, перфорированная плита — до 14×; теперь 1,0–1,6×). Замкнутая гравировка — как в детали.

Место под подвод — правило то же: врезка внешнего контура со свободой ≥ 10 мм; нет такой — самый свободный угол, но
любой из одинаково свободных (у плотных рядов это 2,0 мм у всех углов), а не первый.

Общий рез: каждый порядок группы строится без «взгляда вперёд» и с ним (coedge.build_group look), лучший — по ключу
стратегии (прототип брал «взгляд» всегда — один лист m30 ухудшился 14 → 15). Безопасные (`_coedge_pool`): проходы по
порядкам единиц (ближайший сосед, замкнутый обход в обе стороны — без повторов) и проход `short`; у последней единицы —
лучшая без возврата и лучшая с возвратом; у последней большой группы — ещё и обходы в обратную сторону, а «взгляд
вперёд» последней детали смотрит на возврат в ноль (`final`): угол врезки и сторона последнего куска цепочки — по
переходу в ноль. m3: возврат 2,97 м над деталью → 0,80 м не над ней. Ограничение: блок кончается на общей кромке —
если на листе одна группа и любая её кромка у нуля общая (решётки: три решётки столбиком), возврат над деталью не
обойти — safe0 там = safe, сводка честно показывает возврат. Исправлено по ревизии: путь по детали группы с «взглядом
вперёд» считал уход к следующей детали дважды. Формат блока не менялся (заводской тест 7/7 точно).

Сохранено: прежние ключи `res["crossings"]` (`tongues`, `parts`) считаются как раньше, новые — рядом (`holes`,
`holes_small`, `freed_small`, `freed_parts`, `freed_mj`, `near`, `short`, `cut_tongues`); полный счёт — `res["risk"]`.
Маршрут со стратегией `dict(key="short")` (без новых переключателей) повторяет 50ed4af фигура в фигуру на всех
образцах — ускорения ниже его не меняют.

Скорость (маршрут на образцах ≤ 2× прежнего, m14 целиком ≤ 1,3×): сетка препятствий (`risk.Grid`) для подвода,
заходов и счёта (m14: подвод 30 с → 0,2 с); отбор по габаритам; оптимизатор пути по детали (`order`) — те же
сравнения в том же порядке, но стыки посчитаны заранее и перебор мест — списками (в 3,4 раза быстрее; на 4903
случайных и деталях образцов — тот же путь, что у 50ed4af); `geom.inside` — без индексов (те же пары рёбер); в
группах общего реза — разбиение контуров один раз на группу, габариты рёбер — в кэше, кэш «взгляда вперёд»; счёт
готового маршрута берёт препятствия и вырезанное из плана деталей.
