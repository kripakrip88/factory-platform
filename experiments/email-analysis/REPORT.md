## Выводы для проектирования маршрута «письмо → лид»

**Поток реальный и плотный.** ~23 письма/день, пик 37. Заявки — **31%** (125 из
400). Спам 17%, прочее 52%. Значит включать `append_to=Lead` в лоб НЕЛЬЗЯ —
2 из 3 писем создали бы мусорный лид. **Классификатор-фильтр перед созданием
лида обязателен** (это и подтверждает архитектуру n8n + Claude).

**Где живёт заявка (Блок 3) — определяет фазы.**
- Только тело: **29** (23%) — это «лёгкая» доля, покрывается маршрутом без чтения
  вложений.
- Смешанное (тело + вложение): **73** (58%) — суть частично в тексте; маршрут
  «текст тела + прикрепить файлы как есть» закроет бóльшую часть, но без чтения
  вложения часть деталей потеряется.
- Только во вложении (PDF/Excel/Word без сути в теле): **20** (16%) — для них
  нужен парсинг вложения, иначе лид будет пустой.

  → **Старт без распознавания вложений покрывает ~81%** заявок хотя бы частично
  (тело + смешанные), но качество по 58% «смешанных» будет неполным. Чтение
  вложений (особенно Excel и PDF-текст) — следующая фаза, не первая.

**Реализуемость извлечения из текста (Блок 4) — высокая.** Контакт 19/20,
суть 17/20, позиции 15/20. Под критерий «7 из 10 верных» запас есть уже на
тексте. Проблемы: расплывчатые запросы (4) и письма без позиций (2) — там суть
часто во вложении.

**Вложения (Блок 5) — массовые.** 93% заявок с вложениями, в среднем 2.4 шт.
Типы: картинки (127) и PDF (97) доминируют, Word 55, Excel 11, CAD 5. Из PDF
**63 с текстовым слоем** (читаемые парсером) против **34 скана** (нужен OCR/зрение).
→ «Единое окно» (прикрепить все файлы к лиду) ценно сразу. Для чтения: сначала
Excel и текстовые PDF (дешёвый парсинг), скан-PDF и картинки/чертежи (OCR/vision)
— позже.

**Рекомендация по старту.** Фаза 1: IMAP → классификация (заявка?) → для заявок
лид из ТЕКСТА тела + прикрепление всех вложений к карточке (без их чтения). Это
даёт рабочий маршрут на ~100% заявок с разным качеством наполнения и закрывает
«единое окно». Фаза 2: чтение Excel + текстовых PDF (поднимет качество 58%
смешанных и 16% «только вложение»). Фаза 3: OCR/vision для сканов и чертежей.
