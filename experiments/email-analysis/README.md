# experiments/email-analysis

**Что это.** Разведка реального потока писем ящика `pmkpark@mail.ru` —
обезличенная статистика, чтобы спроектировать первый маршрут «письмо → черновик
лида» на цифрах, а не на догадках.

**Статус.** Эксперимент. Изолирован (принцип изоляции модулей из `CLAUDE.md`).
Ничего не трогает в основном стеке, ничего не создаёт в ERP, ничего не отправляет.
Только читает почту (IMAP read-only) и считает.

## Приватность (жёстко)
- Запуск ТОЛЬКО на сервере завода. Содержимое наружу не уходит (кроме вызовов
  Anthropic API для классификации — явное требование ТЗ).
- В `REPORT.md` идут только числа/распределения/домены. Тел писем, имён,
  телефонов, реквизитов в отчёте нет.
- Креды (IMAP-пароль приложения, Anthropic API key) — в `.env` (в `.gitignore`).
  В код не хардкодятся, в логи не пишутся.
- Вложения обрабатываются в памяти, на диск не сохраняются.

## Как запустить (на сервере)
```bash
cd /opt/factory-platform/experiments/email-analysis
cp .env.example .env
# заполнить IMAP_PASSWORD (пароль ПРИЛОЖЕНИЯ mail.ru) и ANTHROPIC_API_KEY
python3 -m venv venv && . venv/bin/activate
pip install -r requirements.txt
python3 analyze.py > REPORT.md 2> progress.log
```
`REPORT.md` — обезличенный отчёт (Блоки 1–5). `progress.log` — прогресс (stderr),
не коммитить.

## Пароль приложения mail.ru
Основной пароль от почты для IMAP не подойдёт (нужен app-password):
mail.ru → Настройки → Безопасность → «Пароли для внешних приложений» →
создать → тип «Почта» → вставить в `.env` как `IMAP_PASSWORD`.

## Файлы
- `analyze.py` — скрипт анализа (Блоки 1–5)
- `.env.example` — шаблон кредов (без значений)
- `requirements.txt` — pdfminer.six (детект текстового слоя PDF)
- `erpnext-email-capabilities.md` — записка: что штатный email-модуль ERPNext
  умеет с входящими письмами и вложениями
- `REPORT.md` — результат (генерируется на сервере; обезличен → можно коммитить)
