# experiments/email-module

Разведка и настройка штатного email-модуля ERPNext (изолированный эксперимент).

**Цель:** понять, что Email-модуль ERPNext умеет из коробки, и вживую проверить
главное — долетают ли вложения писем в карточку. Без автоматики, классификации
и автосоздания лидов.

## Статус
- ✅ **Часть 1 — разведка возможностей:** `capabilities.md` (7 вопросов).
- ✅ **Часть 2 — подключение:** эскалация (нет лимита по дате) → Антон выбрал
  рабочий ящик с count-лимитом. Подключён с `initial_sync_count=100` + UNSEEN,
  без автолида, без исходящей. Первая загрузка — 99 писем.
- ✅ **Часть 3 — живая проверка:** письма долетели (101), вложения в системе
  (154 File, все непустые, открываются), привязка к лиду сохраняет вложение.
  Приём после проверки **отключён** (`enable_incoming=0`).

Итог и «что достраивать в Фазе 1» — в конце `capabilities.md`.

## Очистка
Аккаунт «PMK Park входящие (тест)» и 101 письмо с реальными ПД остаются в ERP до
решения Антона. Ящик привязан к Administrator, приём включён — письма идут в работу с понедельника.

## Приватность
- Подключение/проверка — только на сервере. Тела писем и ПД в git/отчёты не
  выносятся. Скриншоты обезличиваются.
- Креды (пароль приложения mail.ru) — через защищённое поле ERPNext, не в git/чат.
- Автосоздание лидов (`append_to`) НЕ включаем; исходящую почту НЕ настраиваем.
