# Штатный email-модуль ERPNext: возможности (живая разведка)

Проверено по коду установленного инстанса (frappe v16:
`email/doctype/email_account`, `core/doctype/communication`, `email/receive.py`,
`email/inbox.py`) + структура полей доктайпов. Прод-конфиг не менялся.

## 1. Email Account — подключение входящего по IMAP

DocType **Email Account**. Поля подключения входящего:
- `email_id` (Email Address) — адрес ящика
- `password` (Password) — пароль/пароль приложения (защищённое поле)
- `service` (Select) — пресет провайдера или ручная настройка
- `enable_incoming` (Check) — включить приём
- `use_imap` (Check) — IMAP (иначе POP3)
- `email_server` (Incoming Server) — напр. `imap.mail.ru`
- `incoming_port` (Port) — напр. `993`
- `use_ssl` (Check) + `validate_ssl_certificate` (Check)
- `imap_folder` (Table) — какие IMAP-папки тянуть (INBOX и др.)
- `attachment_limit` (Int, МБ) — лимит размера вложения

**Частота опроса:** отдельного поля «раз в N минут» нет — приём запускает
планировщик Frappe (scheduled job `email_account.pull`) на общем расписании
скедулера (по умолчанию порядка раз в несколько минут). Управляется глобально,
не на уровне аккаунта.

## 2. С какой даты / лимит начальной загрузки — КРИТИЧНО

⚠️ **Настройки «загружать с даты X» (по дате) — НЕТ.** Есть только:
- `initial_sync_count` (Select: **100 / 250 / 500**, по умолчанию 250) — сколько
  писем тянуть при ПЕРВОЙ синхронизации. Минимум через выпадашку — **100**.
- `email_sync_option` (Select: **UNSEEN** / ALL, по умолчанию UNSEEN) — тянуть
  только непрочитанные или все.

То есть ограничение **по количеству**, а не по дате. Для ящика на 22 000+ писем
это значит: безопасный потолок задаётся `initial_sync_count` (мин. 100) +
`email_sync_option=UNSEEN`. «Ровно за 3 рабочих дня» штатно выставить нельзя
(при ~23 письма/день 100 писем ≈ ~4 дня — близко, но это счётчик, не дата).

→ **Это срабатывает как условие эскалации из ТЗ** (нет настройки по дате). См.
раздел «Решение по подключению» ниже.

## 3. Вложения — куда попадает файл

`receive.py → save_attachments_in_doc()` (строка 615): каждое вложение входящего
сохраняется как отдельная запись **File** с привязкой:
- `attached_to_doctype = "Communication"`, `attached_to_name = <это письмо>`
- `is_private = 1` (приватный файл), содержимое сохраняется в системе
- `MaxFileSizeReachedError` обходится (вложение сверх лимита пропускается)

На самом Communication ставится флаг `has_attachment`. **Вывод: вложения
реально захватываются и хранятся в системе, привязанные к письму
(Communication).** (Открываемость проверяется вживую — Часть 3, отложена, см.
ниже.)

## 4. Communication — хранение и привязка

Входящее письмо хранится как **Communication** с полями:
- `communication_medium = Email`, `sent_or_received = Received`
- `email_account` — из какого ящика
- `reference_doctype` (Link) + `reference_name` (Dynamic Link) — **привязка к
  любому документу**: Lead, Customer, Contact и т.д.
- `has_attachment` — есть ли вложения

При привязке письма к Lead (через reference) письмо появляется в **таймлайне
карточки лида**. Вложения остаются File-записями на Communication и доступны
через это письмо в таймлайне. (Появляются ли они в собственной панели
вложений Lead — проверка вживую, Часть 3.)

## 5. Email Inbox — рабочее место менеджера

Да, штатный инбокс есть: `email/inbox.py` + view `frappe/public/js/frappe/
views/inbox`. Открывается по `/app/communication/view/inbox`. Логика:
- читает **User Email** (к каким Email Account привязан пользователь) и показывает
  входящие/исходящие по каждому ящику, как почтовый клиент;
- при нескольких ящиках — выбор «All Accounts» или конкретного;
- менеджер видит список писем, открывает, видит вложения.

То есть «единое окно входящих» из коробки есть — это представление инбокса над
Communication.

## 6. append_to — автосоздание документа из письма

`append_to` (Link на Email Account) задаёт DocType, который **автоматически
создаётся** из каждого входящего (`receive.py → _create_reference_document`):
тема → поле имени, отправитель → email. Если выбрать «Lead» — каждое письмо
поднимет лид.

**Отключается просто — оставить `append_to` ПУСТЫМ.** Тогда входящие хранятся
как Communication (+ вложения), но никакие документы не создаются. Это ровно наш
режим на старте: **никакого автолида**, классификатор будет отдельной фазой.

## 7. Чего НЕ умеет из коробки (для нашей цели)

| Нужно | Штатно | Достраивать |
|---|---|---|
| Загрузка «за 3 дня» (по дате) | Только по количеству (`initial_sync_count`, мин 100) + UNSEEN | Точную дату — нет; либо count-лимит, либо внешний фетч |
| Фильтр спама перед попаданием в работу | Нет — все письма падают в Communication/инбокс | Классификатор (n8n + Claude), Фаза 2 |
| Вложения как attachments самого Lead | Файлы висят на Communication (видны в таймлайне лида) | Хук, копирующий/перепривязывающий File на Lead — проверить вживую необходимость |
| Извлечение структуры (позиции, кол-во) в поля лида | Нет — только тема→имя, отправитель→email | AI-извлечение (наш слой) |

**Что берём готовым:** приём IMAP + захват вложений в Communication + инбокс-UI +
ручная привязка письма к Lead через reference + отключение автолида (пустой
append_to). Это закрывает костяк «единого окна».

**Что достраивать в Фазе 1:** (а) ограничение объёма при подключении большого
ящика — штатно только по количеству; (б) при необходимости — хук, чтобы вложения
были видны прямо в карточке лида, а не только в таймлайне письма.
