# VPN-сервер: синхронизация ключей сотрудников с Odoo

**Статус:** 28.10.2026 — написано и проверено (тесты + прогон на настоящем
Xray на отдельных портах). На VPN-сервер **не установлено**. Модуль Odoo —
`experiments/odoo/addons/pmk_vpn`.

## Зачем

Сотрудникам — личные ключи VPN через бота @Dv_laba_bot: у каждого свой
QR-код, не больше 3 устройств одновременно, трафик виден по человеку, раздал
ключ — отключается только он.

## Как устроено

```
Odoo (erppark.ru)                         VPN-сервер (31.77.141.89, NL)
  pmk_vpn: ключи, QR, бот        ◀── раз в минуту ──  vpn_sync.py (служба vpn-sync)
  /pmk_vpn/sync                  трафик, адреса,      │ xray api: ключи, статистика,
                                 параметры сервера ──▶│ отключение лишних адресов
                                 ◀── список ключей ───┘
```

* **Odoo никуда не ходит.** Всегда приходит VPN-сервер. Если он недоступен,
  Odoo и бот работают как обычно (правило 11 CLAUDE.md).
* **Odoo недоступен** — работают ключи из последнего ответа, трафик копится и
  уходит со следующей удачной отправкой.
* **Ключи меняются без перезапуска Xray** (`xray api adu/rmu`), у остальных
  соединения не рвутся. Если Xray перезапустится, ключи сотрудников из API
  пропадут, и синхронизация вернёт их в течение минуты.
* **Лимит устройств.** Пускаются первые 3 адреса ключа по времени подключения.
  Четвёртый отключается правилом `user + source → block` только у этого ключа
  на 15 минут, и дальше, пока остаётся лишним. Если одно из первых устройств
  ушло, отключённое входит в лимит. Администратору раз в сутки приходит тревога
  с кнопками «Новый ключ» и «Отключить».
* **Управляет только ключами `u<номер>`** (номер пользователя Odoo, без ФИО).
  Личные ключи Антона и семьи (`anton`, `anton-x`) не трогает, не считает и не
  ограничивает.
* **Параметры ссылок** (адрес, порты, публичный ключ Reality, домен
  маскировки) VPN-сервер сам отдаёт в Odoo. В репозитории их нет.

## Файлы

| Файл | Что |
|---|---|
| `vpn_sync.py` | синхронизация; только стандартная библиотека Python |
| `vpn-sync.service` | служба systemd (от nobody, раз в 60 с) |
| `install.sh` | установка на VPN-сервер |
| `tests/test_vpn_sync.py` | тесты на подставном Xray: `python3 -m unittest discover -s experiments/vpn/tests` |

## Установка (после выкладки pmk_vpn в Odoo)

```bash
scp experiments/vpn/{vpn_sync.py,vpn-sync.service,install.sh} vpn:/root/vpn-sync/
ssh vpn 'bash /root/vpn-sync/install.sh 31.77.141.89'
```

Скрипт печатает секрет. Тот же секрет записать в Odoo:

```python
env["ir.config_parameter"].set_param("pmk_vpn.sync_token", "<секрет>")
```

Проверка: `journalctl -u vpn-sync -n 20`. Если ошибок нет, через минуту в
Odoo → Настройки → VPN-ключи можно нажать «Разослать ключи». Это отправит
сообщения сотрудникам, поэтому только по решению Антона.

Изменения в конфиге Xray, которые делает установка (`--prepare-config`), и
откат:

* добавляются `api` (127.0.0.1:10085), `stats`, `policy.levels.0` (статистика
  по пользователям) и метка `reality-tcp` у основного входа;
* копия конфига лежит рядом: `config.json.bak-vpnsync-*`;
* откат: `systemctl disable --now vpn-sync`, вернуть копию конфига,
  `systemctl restart xray`.
